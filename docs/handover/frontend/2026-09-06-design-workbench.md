# 独立 Design 工程初版

日期：2026-09-06

## 交付入口与定位

分支：`feat/design-workbench`。仓库根目录的 `design/` 是独立 React/Vite 包，执行 `pnpm --dir design dev` 后打开 http://127.0.0.1:5180。它收录现有产品页面、组件和交互场景，供下一项 UI 需求直接在完整界面里设计。

本轮没有改动正式前端 `src/` 的产品实现。正式前端仅新增测试侧原版参考入口与独立类型检查配置；不进入正式构建入口。

## 工程结构

- 产品画布与工作台为不同 HTML 文档，样式和视口隔离。工作台提供场景、尺寸、版本、回放、重置与待确认记录导出。
- 展示组件从 source commit `7d01cfa6b542f98ee67d8a54a437748a60f4c190` 提取为独立代码，保留现有 token、Markdown、图标、菜单、选择和滚动实现。
- 本地演示状态只负责页面切换、草稿、消息过程及有限成功/失败结果；没有 API transport、JWT、SSE、业务 reducer 或后端副本。
- 演示数据不读取真实账户。用户文件只形成浏览器 Blob URL，离开画布时回收；分享快照使用 `piko-design.shared-snapshots.v1`，供同一 Design origin 的独立标签页读取。
- `catalog/sources.json` 记录提取来源及哈希，`coverage.json` 映射场景与验证，`baseline.json` 标识当前源码内容。未提交版本用内容指纹辨认，不能填写虚构的 design commit。

## 页面与实际操作

40 个入口覆盖聊天、欢迎页、长内容、收起侧栏、未验证提醒、来源、引用、附件、上传失败、发送失败、思考/工具/正文/失败/取消、搜索及其失败/等待、分享弹窗/我的分享/公开页及无效/等待、账号及错误结果、登录/注册/找回密码、邮箱验证、密码重置、注销确认、模型管理/访问门禁/错误结果，以及组件目录。

页面内仍通过原有控件操作，而非每个按钮弹出统一成功提示：发送与停止、编辑和重发、搜索选择及回源、文本选择引用、草稿切换、附件移除/重试、账号表单、头像裁剪、分享创建和撤销、模型编辑与锁定。服务驱动的成功/失败使用有限本地回调。

“错误”入口一般在首次对应操作时报错，随后重试成功；“等待”入口由工具栏“完成等待”释放。重置重建画布并恢复样本。生成过程可暂停或单步，不需要真实模型。

## 验证方法与证据

当前配对集覆盖 27 个页面/结构状态，每个在桌面与移动尺寸运行；其余场景由渲染检查和连续交互验证覆盖。配对与渲染烟测是两种不同证据，不能把所有目录项都写成已逐像素验证。

配对用原版测试入口运行正式组件，Design 使用独立组件。两端统一合成内容、日期、视口和浏览器；统一滚动与焦点，循环动画固定时点、有限过渡推进到结束。Pixelmatch 使用 threshold=0.05、includeAA=true、差异像素数必须为零；原始差异数同时保留。没有遮挡 mask 或差异面积豁免。

真实 Chrome 测量思考标题相对消息的 top/height 跨阶段稳定，检查 759/760/761px 断点。交互检查覆盖发送/停止/恢复、失败重试、搜索键盘选择、账号编辑、登录、附件、文本选择引用、候选隔离、头像、分享和模型编辑。

输出在 `design/output/`，CI 上传与 commit 关联的截图、差异图、几何数据、报告和失败 trace。原版浏览器参考不连接业务服务，单独运行在 5183；Design 测试在 5182。

最终本地验证结果见本记录末尾。CI 工作流已提供，远端结果需要推送后才能产生，不能将本地通过表述为远端 CI 已通过。

## 下一项 UI 需求

在 `src/proposals/registry.ts` 增加候选，复用既有页面和局部组件。新状态进入场景目录；候选 CSS 只覆盖候选文档，结构变体按 proposal 选择，不能让 current 跟着改变。`example-composer` 是隔离演练，未获产品变更批准。

用户确认后在 `approvals/` 保存需求、设计版本、场景、截图与确认范围。正式前端按该版本实施，对照后记录 implementation commit，再提升为 current。生产紧急修复需要回补 Design。详细操作见 [使用说明](../../../design/README.md)。

## 已知边界

- 该工程可作为新 UI 需求的完整页面基础；不会自动生成未来业务的新状态，也不是拖拽式 Figma 编辑器。
- 固定浏览器下的配对不是所有操作系统和所有任意状态组合的数学等价证明。真实 iOS/Android 软键盘、原生选区和系统剪贴板权限尚无本轮真机证据，延续原版已有平台限制。
- 服务耗时、后台并发、上传协议、邮件投递和业务持久化不在 Design 中重建；真实业务正确性仍由生产工程验证。
- 依赖中保留 Markdown/数学/代码高亮所需能力。Vite 的大 chunk 提示及 CSS 优化器对 `::highlight` 的提示与原版同类，未通过删除功能或屏蔽警告改变产品效果。
- 首版 current 等待用户审阅；没有伪造 approval 记录。
