# 申请密码重置（发信 + 防枚举）

Type: feature

Status: completed

Blocked by: 01

## What to build

匿名用户在忘记密码时提交邮箱申请重置：无论邮箱是否注册、是否已停用，接口一律恒定返回成功（「如果该邮箱已注册，重置邮件已发送」语义）；仅当邮箱属于存在且未停用的用户时才真正签发 `password_reset` 令牌（30 分钟 TTL，独立配置项）并经 outbox 发出品牌化重置邮件。console provider 下可端到端演示收信。

## Acceptance criteria

- [ ] 存在且未停用的邮箱：签发令牌、outbox 入列、邮件含指向前端重置页的 30 分钟有效链接；恒定成功响应。
- [ ] 不存在的邮箱与已停用账户的邮箱：响应与成功场景完全一致，不签发令牌、不发信。
- [ ] 限流按 register 模式：IP 限流 fail-open + 邮箱冷却（60 秒，按 `password_reset` purpose 独立计，不与验证邮件挤占）；Redis 故障时降级为数据库冷却，接口保持可用。
- [ ] 不存在的邮箱同样占用冷却 key——429 出现与否不泄露注册状态。
- [ ] 重置邮件模板复用品牌化 HTML 卡片渲染器，渲染器单元测试扩展覆盖。
- [ ] 新 TTL 配置项与限流参数进入配置模型和环境变量模板。
- [ ] HTTP API 层测试覆盖上述全部外部行为（复用邮箱验证 API 测试的缝）。
