# Cloudflare R2 用户头像上传

Type: feature
Status: ready-for-human
Blocked by: None

日期：2026-07-14
需求来源：本分支 `/grill-with-docs` 设计确认会话
术语依据：根目录 `CONTEXT.md`（邮箱验证 / 注销 / 停用）
相关决策：账户注销继续采用软停用，但公开头像是经用户明确确认的即时物理删除例外；实施时须同步修订既有账户注销 ADR，避免与“数据原样保留”表述冲突。

## Problem Statement

用户目前只能在账号卡片中选择本地图片并查看一次性预览，图片不会上传、持久化或同步到其他设备。关闭页面后头像即恢复为昵称首字母，侧栏个人中心、用户菜单和退出确认框也无法展示用户选择的头像。

产品需要为已完成邮箱验证的用户提供可靠的头像上传与替换能力，同时避免让未经验证的原始文件进入公开对象存储。该能力必须在浏览器直传 Cloudflare R2 的前提下控制后端带宽，并覆盖文件伪装、超大图片、并发覆盖、任务丢失、孤儿对象、CDN 陈旧缓存、账户注销和云服务短暂故障等生产问题。

头像是当前唯一文件上传用途。本期不应因尚未定义的聊天附件需求而提前建设通用文件资产领域。

## Solution

在现有账号卡片中加入正方形头像裁剪流程。用户在浏览器本地选择 JPEG、PNG 或静态 WebP 原图，完成拖动和缩放后，由浏览器生成一张固定规格的 `1024×1024` 静态 WebP 中间图。原图不离开用户设备。

前端向 FastAPI 创建头像上传会话，获得绑定文件大小和固定内容类型的短期 R2 预签名 PUT URL，然后将裁剪后的中间图直接上传到私有临时 bucket。上传完成后，前端携带 R2 ETag 确认上传；确认事务把数据库会话置为 `queued`，再尽力向独立媒体 Celery queue 投递任务。

媒体 worker 从私有 bucket 下载中间图，不信任浏览器声明，按真实字节验证格式、静态属性、尺寸、大小和可解码性，再去除元数据并重新编码为 `512×512 WebP`。只有服务端生成的成品能够写入公开 bucket。成品使用不可预测且不含用户信息的版本化对象键，通过独立资源域名和 Cloudflare CDN 长期缓存。

头像替换采用原子切换：旧头像保持可见，直到新对象写入成功且数据库提交新的当前对象键。切换完成后，旧对象进入持久化删除任务，由 Celery 周期清理负责删除 R2 源对象并按完整 URL purge CDN 缓存。账户注销具有最高优先级，会使所有在途头像任务失效并永久删除当前公开头像。

PostgreSQL 是上传状态和补偿任务的事实源；Redis/Celery 只负责投递与唤醒。Celery beat 负责恢复滞留任务、清理过期临时对象、重试旧头像删除和 CDN purge，并清除达到保留期的历史会话。

## User Stories

1. 作为已完成邮箱验证的用户，我想上传自己的头像，以便个人中心不再只显示昵称首字母。
2. 作为已有头像的用户，我想上传新头像替换旧头像，以便随时更新个人形象。
3. 作为用户，我想在上传前看到正方形裁剪界面，以便决定最终头像中显示的区域。
4. 作为用户，我想通过拖动图片调整裁剪位置，以便人物或主体处于合适位置。
5. 作为用户，我想通过缩放调整裁剪范围，以便控制头像构图。
6. 作为触屏设备用户，我想使用触控手势完成移动和缩放，以便在手机上完成头像设置。
7. 作为键盘或辅助技术用户，我想获得可理解的裁剪操作提示和可访问控件，以便不依赖精确鼠标操作。
8. 作为用户，我想在确认前看到圆形头像预览，以便理解正方形成品在实际界面中的显示效果。
9. 作为注重隐私的用户，我希望原始照片不离开我的设备，以便只上传我明确裁剪后的区域。
10. 作为用户，我希望系统接受常见的 JPEG、PNG 和静态 WebP 原图，以便直接选择常用照片。
11. 作为选择了不支持格式的用户，我想得到明确提示，以便改用 JPEG、PNG 或 WebP。
12. 作为选择了动画图片的用户，我想知道头像只支持静态图片，以便理解为什么文件被拒绝。
13. 作为选择了过大文件的用户，我想在上传前就得到提示，以便避免等待无效上传。
14. 作为选择了像素异常图片的用户，我想在浏览器解码阶段得到提示，以便避免设备卡顿。
15. 作为选择了过小图片的用户，我想知道头像可能不符合最低要求，以便换用更清晰的图片。
16. 作为用户，我希望裁剪完成后上传体积较小的中间图，以便在移动网络上快速完成设置。
17. 作为用户，我希望上传流量直接进入 Cloudflare R2，以便后端服务器不会成为大文件传输瓶颈。
18. 作为用户，我希望上传权限只在短时间内有效，以便泄露的上传链接不能长期使用。
19. 作为用户，我希望上传后能看到“处理中”状态，以便知道头像尚未丢失或卡住。
20. 作为用户，我希望处理完成后个人中心所有现有头像位置同步更新，以便界面保持一致。
21. 作为用户，我希望替换头像时旧头像继续显示，直到新头像真正可用，以便不会出现空白或损坏头像。
22. 作为用户，我希望新头像处理失败时旧头像保持不变，以便失败不会破坏当前资料。
23. 作为首次上传的用户，我希望处理期间继续显示昵称首字母，以便界面始终有稳定回退。
24. 作为关闭账号卡片的用户，我希望已经提交的处理任务继续执行，以便不必一直等待弹窗。
25. 作为刷新页面的用户，我希望已经提交的后台处理继续完成，以便网络或页面刷新不会丢失请求。
26. 作为尚未提交裁剪就刷新页面的用户，我接受重新选择图片，以便系统不必公开读取私有临时图来恢复编辑状态。
27. 作为遇到暂时性云服务故障的用户，我希望系统自动重试处理，以便短暂故障不会立即要求我重传。
28. 作为处理最终失败的用户，我想得到稳定且可理解的失败提示，以便重新发起上传。
29. 作为重复点击确认的用户，我希望接口保持幂等，以便网络重试不会创建多个头像。
30. 作为在多个标签页修改头像的用户，我希望最新发起的上传会话拥有生效资格，以便旧页面不能覆盖新选择。
31. 作为连续选择多张图片的用户，我希望旧的未完成会话自动失效，以便结果符合最近一次意图。
32. 作为用户，我希望头像 URL 不包含数据库 ID、用户名、邮箱或原文件名，以便公开资源地址不泄露身份信息。
33. 作为用户，我希望头像加载失败时自动回退到昵称首字母，以便资源故障不破坏个人中心。
34. 作为用户，我接受本期不能单独移除头像，以便产品范围保持为上传和替换。
35. 作为未验证邮箱的用户，我希望上传入口引导我先完成邮箱验证，以便理解公开资源上传为何受限。
36. 作为已验证邮箱的用户，我希望正常上传不要求再次输入密码，以便资料更新流程保持轻量。
37. 作为完成注销的用户，我希望公开头像被永久删除并清除 CDN 缓存，以便保存过旧 URL 的人也不能继续访问。
38. 作为完成注销的用户，我希望所有尚在处理的头像任务失效，以便停用后不会重新发布头像。
39. 作为由运维恢复的停用用户，我理解旧头像不会恢复，以便账户恢复与公开头像隐私边界清晰。
40. 作为平台运营者，我希望只有已登录、active 且邮箱已验证的用户能创建上传会话，以便降低公开对象存储滥用。
41. 作为平台运营者，我希望每用户和每 IP 都有上传会话频率限制，以便控制 R2、CPU 和存储成本。
42. 作为平台运营者，我希望 Redis 故障时拒绝创建新上传会话，以便失去限流保护时不开放资源消耗入口。
43. 作为平台运营者，我希望客户端无法指定 bucket、对象键或成品 URL，以便对象命名和访问控制由服务端掌握。
44. 作为平台运营者，我希望浏览器上传只能进入私有临时 bucket，以便未经验证字节永远不出现在公开域名。
45. 作为平台运营者，我希望公开 bucket 只包含服务端重新编码的静态 WebP，以便公开资源边界可审计。
46. 作为平台运营者，我希望 API、媒体 worker 和 CDN purge 使用不同的最小权限凭证，以便单个服务泄露时缩小影响范围。
47. 作为平台运营者，我希望开发与生产使用独立 bucket，以便测试不会污染或删除生产头像。
48. 作为平台运营者，我希望普通 CI 使用 fake 存储，以便测试不依赖 Cloudflare Secret 和外部网络。
49. 作为平台运营者，我希望数据库记录头像上传状态，以便 Redis 消息丢失后仍可恢复任务。
50. 作为平台运营者，我希望 Celery beat 重新投递滞留的 queued 会话，以便 API 发布消息失败不会永久卡住头像。
51. 作为平台运营者，我希望超时的 processing 会话可通过 lease 恢复，以便 worker 崩溃不会留下永久处理中状态。
52. 作为平台运营者，我希望重复 Celery 消息不会重复发布或删除错误对象，以便任务满足幂等要求。
53. 作为平台运营者，我希望临时对象在会话过期后自动删除，以便取消操作不会形成长期孤儿文件。
54. 作为平台运营者，我希望旧头像删除失败时进入持久化补偿队列，以便数据库切换成功后不会永久泄漏旧对象。
55. 作为平台运营者，我希望删除 R2 对象时同时 purge 对应 CDN URL，以便长期缓存不会破坏隐私删除语义。
56. 作为平台运营者，我希望清理任务对“对象已不存在”视为成功，以便重试保持幂等。
57. 作为平台运营者，我希望上传会话在补偿完成后仅保留七天，以便有排障窗口但不永久积累行为历史。
58. 作为平台运营者，我希望日志使用 upload ID 关联 API、数据库和 worker，以便跨服务排查单次上传。
59. 作为平台运营者，我希望日志不记录预签名 URL、原文件名或图片内容，以便避免泄露上传凭证和个人信息。
60. 作为平台运营者，我希望看到处理耗时、重试次数、清理积压和最老积压时间，以便发现媒体链路故障。
61. 作为运维人员，我想按用户查询当前头像对象和在途任务，以便处理用户支持请求。
62. 作为运维人员，我想按用户下架头像并触发 CDN purge，以便处理违规内容或安全事件。
63. 作为运维人员，我想手工重试删除和 purge 补偿任务，以便在自动重试耗尽后恢复系统一致性。

## Implementation Decisions

### 产品与交互

- 头像能力只覆盖现有个人中心相关头像位置，不改变消息列表布局，也不向公开分享页增加作者头像。
- 没有头像和图片加载失败时使用昵称首字母回退。
- 用户可上传和替换头像，不提供单独移除头像的入口或 API。
- 本期不接入自动内容审核；必须提供运维按用户下架头像的流程。
- 未验证邮箱的用户不能创建上传会话。前端应引导其先完成邮箱验证，后端必须独立执行该约束。
- 裁剪器固定为 1:1，可使用经过维护性、许可证、包体积和 React 兼容性核验的轻量第三方依赖，并封装在项目自己的头像裁剪组件之后。

### 浏览器原图与中间图

- 浏览器本地原图只接受 JPEG、PNG 和静态 WebP。SVG、GIF、动画 WebP、HEIC/HEIF、BMP、TIFF 等不在支持范围。
- 原图在浏览器侧限制为最大 10 MiB、最大 2000 万像素、最长边 8192 px、最小 128×128 px。原图不上传，因此这些限制是用户体验和客户端资源保护，不构成服务端安全边界。
- 用户完成正方形裁剪后，浏览器生成固定 1024×1024、质量 90、保留透明通道的静态 WebP Blob，最大 2 MiB。
- 原图不离开用户设备。服务端不接收原图、裁剪坐标、原文件名或 EXIF 元数据。
- 只有中间 Blob 已生成且大小已知后，前端才创建上传会话。

### 上传 API 与状态机

- 在既有当前用户认证资源下增加三个头像上传端点：创建会话、确认上传、查询状态。
- 创建会话请求只提交 `size_bytes`。内容类型固定为 `image/webp`，对象键、bucket 和请求头由服务端决定。
- 创建会话响应包含 upload ID、预签名 PUT URL、必须携带的签名请求头、URL 到期时间和会话到期时间。
- 浏览器 PUT 成功后读取 ETag；私有 bucket CORS 必须暴露 ETag。
- 确认请求只提交 ETag，不再提交裁剪坐标。后端 HEAD 临时对象，核对对象键、大小、固定内容类型和 ETag 后进入排队状态。
- 查询接口返回 `pending / queued / processing / succeeded / failed / expired`。成功时返回新的头像 URL；失败时返回稳定错误代码和可展示提示，不暴露 R2、图像库或内部堆栈细节。
- 注册、登录、刷新令牌、当前用户查询和资料更新响应都增加可空头像 URL。前端会话状态统一持有该 URL，组件不得自行拼接资源域名。
- 预签名 PUT URL 有效期为 10 分钟，上传会话有效期为 30 分钟。
- 确认接口幂等；已经成功或进入处理的同一会话重复确认不会产生第二个成品。

### 并发语义

- 同一用户只有最新创建的未完成上传会话具有发布资格。创建新会话会使更早的 pending、queued 或 processing 会话失去发布资格。
- worker 开始处理前和切换数据库当前头像前都必须重新检查用户 active 状态及会话当前资格。
- 如果失效任务已生成公开对象但尚未切换数据库，该对象必须进入删除与 purge 补偿。
- 新头像处理期间继续显示旧头像；首次上传则继续显示昵称首字母。处理失败不会改变当前头像。

### 数据模型

- 用户记录增加可空的当前头像对象键。只保存对象键，不保存完整 URL。
- 新增头像上传会话模型，至少记录用户、随机 upload ID、临时对象键、声明大小、ETag、状态、有效期、排队/领取/完成时间、lease、尝试次数、稳定错误代码和最终头像对象键。
- 新增头像删除补偿模型，记录待删除公开对象键、完整 purge URL 或可重建信息、尝试次数、下次重试时间、最后错误和完成时间。
- 头像领域保持专用，不建立通用文件表、文件引用计数、用户文件配额或 asset type 抽象。
- 上传会话在所有对象补偿完成后保留七天；仍关联未完成删除或 purge 时不得物理清除。

### R2 存储边界

- 每个环境使用私有临时 bucket 和公开成品 bucket，开发与生产相互隔离。
- 私有键为 `avatar-uploads/{random-upload-uuid}.webp`，公开键为 `avatars/{random-avatar-uuid}.webp`。随机标识不得包含用户 ID、用户名、邮箱、时间序列或原文件名。
- 私有 bucket 不绑定公开域名。公开 bucket 绑定独立资源域名。
- API 凭证只具备签发私有 bucket 写入所需权限；媒体 worker 凭证负责读取/删除临时对象及创建/删除公开对象；CDN purge 使用独立最小权限 Token。
- 生产临时 bucket CORS 只允许生产 SPA Origin，开发临时 bucket 只允许明确列出的本地 Origin；不使用 Origin 通配符，Cloudflare Pages 预览默认不获得生产上传权限。
- 公开 bucket 只接受服务端生成的成品，不提供浏览器写入路径。

### 媒体处理

- 使用独立 Celery media queue 和独立媒体 worker，避免图片处理阻塞认证邮件 worker。
- worker 根据真实文件字节验证静态 WebP、1024×1024 尺寸、2 MiB 上限和安全可解码性，不信任对象元数据或请求声明。
- worker 去除元数据，保留透明通道，重新编码为单一 512×512 WebP，质量 82。不保留用户原图，也不生成多尺寸变体。
- 成品写入成功后再通过条件数据库更新切换当前头像。条件不成立时不得覆盖更新，已生成对象进入补偿删除。
- 暂时错误自动重试最多三次，使用指数退避和抖动；永久验证错误直接失败。

### 可靠任务投递

- PostgreSQL 是任务事实源，Redis/Celery 只负责投递和唤醒。
- 确认事务把会话从 pending 条件更新为 queued；事务提交后 API 尽力立即发布 Celery 消息。
- 发布失败不撤销已经确认的会话。Celery beat 扫描滞留 queued 会话并重新投递。
- worker 通过条件领取和 lease 把 queued 置为 processing。重复消息、重复领取和任务重投必须幂等。
- processing lease 超时后由恢复任务重新排队。达到处理尝试上限后标记 failed。

### 替换、注销和删除补偿

- 新头像只有在成品对象写入和数据库切换都成功后才对用户可见。
- 数据库切换成功后，旧头像进入持久化删除任务。删除任务同时负责 R2 DeleteObject 和 Cloudflare 按完整 URL purge；两项都完成才算成功。
- 删除不存在的对象视为幂等成功。删除或 purge 暂时失败进入指数退避重试；长期失败保留记录并输出高等级日志。
- 账户注销具有最高优先级：注销事务使用户所有未完成头像会话失效并清空当前头像键；当前头像进入即时删除与 purge 补偿。在途 worker 不得为停用用户重新发布头像。
- 账户注销仍保留会话、消息等既有业务数据，但公开头像是明确的即时物理删除例外。必须修订既有账户注销 ADR，禁止文档继续笼统承诺“全部数据原样保留”。
- 运维恢复停用账户时不恢复旧头像。

### 自动清理

- Celery beat 每小时触发头像维护调度。
- 清理过期或失效会话的临时对象时使用安全缓冲，避免与刚提交的请求发生时钟竞态。
- 周期任务恢复滞留 queued、过期 processing lease、失败的临时对象删除、旧头像删除和 CDN purge。
- 每批有明确上限，避免积压一次性拖垮 worker。
- 完成补偿且超过七天保留期的上传会话可物理删除。

### 缓存与资源响应

- 成品对象设置 `Content-Type: image/webp` 和一年期 `public, immutable` 缓存。
- 每次替换生成新 URL，不使用查询时间戳破坏缓存。
- 资源域名不使用认证 Cookie。通过对象元数据或 Cloudflare Transform Rules 添加 `X-Content-Type-Options: nosniff` 等静态资源安全响应头。
- 删除头像必须执行按完整 URL 的 CDN purge，不使用全站 purge。

### 限流与故障策略

- 创建上传会话采用用户和 IP 双重 Redis 限流：每用户每小时 10 次、每 IP 每小时 30 次。
- Redis 不可用时 fail-closed，拒绝创建新上传会话。错误响应应可被前端映射为明确提示。
- 确认处理不额外消耗会话创建额度，因为一个会话只能进入处理一次。

### 可观测性与运维

- upload ID 是 API、数据库、Celery 与日志的关联标识。
- 记录状态转换、处理耗时、输入字节数、R2 操作耗时、重试次数、稳定错误代码、删除积压数和最老积压时间。
- 不记录预签名 URL、用户原文件名、图片内容或云凭证。
- 运维文档覆盖按用户查询/下架头像、查看在途任务、重试补偿、验证 bucket/CORS/域名、检查媒体 worker 和执行真实 smoke。
- 本期不新增 Prometheus、Grafana 或外部监控 SaaS。

### Cloudflare 资源管理

- 本期通过 Cloudflare Dashboard 或 Wrangler 手工创建四个 bucket、自定义域名、CORS 和最小权限凭证。
- 仓库保存可复现的中文配置、环境变量、验证和回滚文档，但不提交 Secret。
- 本期不引入 Terraform 或 Pulumi。

## Testing Decisions

- 好测试只断言外部可观察行为：HTTP 状态与响应、数据库状态机、对象存储可观察对象、捕获到的任务投递、用户界面状态和公开 URL 行为；不锁定内部函数调用顺序或第三方 SDK 细节。
- **主后端测试缝**：HTTP API + 真实 PostgreSQL + fakeredis + fake object storage + fake Celery publisher + fake CDN purge。该缝复用现有认证 API 测试的最高层模式，并覆盖创建/确认/查询契约、邮箱验证门槛、用户/IP 限流、Redis fail-closed、ETag/大小校验、状态机、幂等、并发失效、消息发布失败恢复、worker lease、替换原子性和注销竞态。
- **前端测试缝**：真实 React 账号卡片和应用用户状态 + fake API/R2 upload adapter。通过可访问角色操作文件选择、裁剪、上传、处理中、成功、失败、429、未验证邮箱引导和各头像位置同步更新，不直接测试裁剪库内部实现。
- **媒体处理测试缝**：以受控图片 fixture 通过媒体任务入口观察成品字节和数据库状态。覆盖静态 WebP、透明通道、伪装格式、动画、损坏文件、尺寸不符、超限、重试分类及条件切换失败后的对象补偿。
- **清理与注销测试缝**：通过周期任务入口和真实 PostgreSQL、fake R2/purge 观察过期临时对象、旧头像删除、purge 重试、对象不存在幂等、七天保留和停用账户不得重新发布。
- **真实 Cloudflare 集成缝**：显式运行、默认不进普通 CI。使用开发 bucket 验证预签名 PUT、浏览器 CORS、ETag、HEAD、媒体处理、公开自定义域名 GET、缓存、DeleteObject 和按 URL purge，并确保测试对象最终清理。
- **最终浏览器 smoke**：使用已验证邮箱的测试账号走真实选择、裁剪、上传、轮询、替换和注销路径；确认现有个人中心头像全部同步、旧 URL purge、未验证用户被阻止及超限提示正确。
- 普通 CI 不持有生产或开发 Cloudflare Secret，所有外部服务默认使用 fake。
- 后端测试执行前遵守项目既有数据库隔离约定，停止可能抢占测试任务或数据的运行中 worker。

## Out of Scope

- 聊天附件、消息图片、文档上传或任意通用文件管理。
- 通用 files/assets 数据模型、文件引用计数、用户存储配额和多租户资源目录。
- 在消息列表、公开分享页或其他用户可访问页面展示头像。
- 用户主动移除头像并恢复默认头像的产品入口。
- 多尺寸头像、响应式图片集、原图留存或头像历史版本恢复。
- GIF、APNG、动画 WebP、SVG、HEIC/HEIF、视频头像。
- 人脸识别、自动居中、人像分割或背景移除。
- 自动内容审核、举报流程、人工审核后台和申诉机制。
- Cloudflare Images 产品、图片变换服务或 Worker 动态缩放。
- Cloudflare 基础设施即代码。
- 新的 Prometheus、Grafana 或监控 SaaS。
- Cloudflare Pages 预览部署向生产 bucket 上传。
- 停用账户的自助恢复、头像恢复或全部账户数据物理清除。

## Further Notes

- Cloudflare 官方文档确认 R2 预签名 PUT 需要 bucket CORS，且预签名 URL 使用 S3 API 域名，不能替换为自定义域名；公开读取仍可通过 R2 自定义域名接入 Cloudflare Cache。
- 长期 immutable 缓存与隐私删除存在天然冲突，因此 DeleteObject 与按 URL CDN purge 必须作为同一个持久化补偿目标。
- 前端上传的是裁剪后中间图，而不是原图；这使原图限制无法成为服务端安全约束。服务端安全边界只依赖固定 WebP、1024×1024、2 MiB 和真实解码验证。
- 账户注销头像即时物理删除与既有 ADR 的“数据原样保留”表述存在明确例外，必须通过 ADR 修订公开记录，而不能只在实现中静默偏离。
- 部署新增配置至少覆盖：两个 bucket 名称、R2 account/endpoint、API 与 worker 独立凭证、公开资源基址、Cloudflare zone ID、purge Token、预签名 TTL、会话 TTL、上传限流、worker lease/重试和清理批量参数。
