# 头像替换、删除补偿与注销生命周期

Type: task

Status: completed

Blocked by: 03

## What to build

完成头像替换后的旧对象删除、Cloudflare 按 URL purge、过期临时对象清理、历史会话保留以及账户注销竞态处理。

删除与 purge 不能依赖请求内尽力而为日志，必须由持久化补偿记录驱动。账户注销具有最高优先级：使全部在途会话失效、清空当前头像键，并永久删除当前公开头像。该行为是既有软停用 ADR 的显式头像例外。

## Acceptance criteria

- [x] 新头像数据库切换成功后，旧头像进入持久化删除补偿；切换失败时新生成对象进入补偿。
- [x] 删除任务同时完成 R2 DeleteObject 和 Cloudflare 按完整 URL purge，两项均成功后才完成。
- [x] 对象已不存在视为幂等成功；删除或 purge 暂时失败按退避策略重试并保留最后错误。
- [x] beat 每小时按批量上限清理过期/失效会话的临时对象并推进删除补偿。
- [x] 仍有未完成对象补偿的上传会话不会被历史清理删除；全部完成后保留七天再物理清除。
- [x] 注销事务使该用户所有 pending/queued/processing 会话失效，清空当前头像键并创建删除/purge 补偿。
- [x] 在途 worker 无法为停用用户重新发布头像；已生成但未切换的公开对象进入补偿。
- [x] 运维恢复停用用户时旧头像不会自动恢复。
- [x] 提供可调用的运维下架能力或明确的安全运维入口，可按用户清空头像并触发相同补偿流程。
- [x] 测试覆盖替换、对象不存在、purge 失败、长期积压、七天保留、注销竞态和恢复后无头像行为。
