# 在上传前处理模型兼容与图片草稿冲突

## 目标

让用户在不支持图片的模型下选择图片时立即得到明确恢复动作，并确保任何拒绝都发生在上传会话、消息和 Run 创建之前。

## 交付范围

1. 文件选择器、粘贴和拖放三条入口在创建上传前按当前模型能力拦截图片，文档仍可正常上传。
2. 混合选择图片和文档时提供“切换 GPT 并上传全部”“仅上传文档”和取消三种动作，保持被保留文件的相对顺序。
3. GPT 草稿已有图片时，切换非视觉模型不会丢弃草稿；用户可继续使用 GPT，或移除/取消全部图片后保留文字和文档完成切换。
4. 四个 Run 创建入口执行同一服务端权威校验；非视觉模型新引入图片时返回 422 与稳定 machine code，且无归档、绑定或 Run 副作用。
5. 前端只按 machine code 选择恢复动作，不解析英文 detail。

## 验收

- [x] DeepSeek 下选择、粘贴或拖入图片时，上传 API 调用次数为零。
- [x] 混合文件的三个用户动作分别得到预期模型、文件集合和原始顺序。
- [x] 切换模型失败或取消不会丢失文字、文档或图片草稿。
- [x] 所有消息创建、继续发送、编辑和重新生成入口在不兼容时均零数据库副作用。
- [x] 取消上传失败仍由既有待绑定文件期限最终回收配额。

## 非目标

- 本票不实现已有视觉历史导致的会话级模型约束。
