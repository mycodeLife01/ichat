# 独立 Design 工程：初版开发需求与实现方案

日期：2026-09-06

状态：工程已落地，本地机器验证通过，等待用户视觉验收。使用入口见 [Design README](../../design/README.md)，实际实现与证据范围见 [初版交接](../handover/frontend/2026-09-06-design-workbench.md)。用户确认采用独立 React、覆盖现有前端页面、专注 UI，并明确首版以绝大部分实际开发场景的准确还原为目标，后续按效果迭代；不追求所有平台和任意状态组合的绝对等价证明。

## 1. 目标与完成定义

在仓库根目录建立 `design/`，作为 iChat 长期维护、可交互、可版本化的设计源稿。用户通过浏览器审阅和体验，agent 通过源代码、场景说明及固定版本理解设计，再实现到 `frontend/`。

初版交付必须同时满足：

1. 完整收录当前前端所有已有页面、用户可见控件和关键交互状态，包括工作台之外的认证、分享和模型管理页面；不能以聊天页 demo 代替整体验收。
2. 在相同内容、环境、视口和状态下，Design 与当前前端的外观、布局、文字、操作反馈和交互顺序一致；不能只有“大致相似”的静态画面。
3. 不依赖 API、数据库、LLM、对象存储、邮箱或真实登录即可使用；安装依赖后独立启动、构建和预览。
4. 已具备新增 UI 需求的完整路径：在既有完整页面中制作候选方案、审阅、固定确认版本、指导实现和对照验收。
5. 工程只维护展示和交互所需内容，不成为另一套业务应用。

本文保留初版需求与实施设计；交付时以第 12 节及交接文档的实际证据说明可用范围，不将机器验证等同于用户批准。

## 2. 基线、权威来源与“一模一样”的含义

### 2.1 首版来源

初始源代码基准为当前工作区创建本分支时的提交：

`7d01cfa6b542f98ee67d8a54a437748a60f4c190`

当时工作区无未提交修改。基准是该版本的 `frontend/`，不假定线上部署版本与之相同。开始实施时记录最终采用的 source commit；如果前端已变化，列出差异并在开始提取前明确是否更新基准，不得迁移到一半无记录地混用版本。

来源优先级：

1. 指定 source commit 的真实前端渲染和可观察交互，以及该版本代码。
2. 当前前端架构和最新功能交接文档，用于解释规则及已知限制。
3. 历史设计稿作为背景资料，不能用旧 HTML 原型覆盖已实现 UI。

代码、文档与浏览器结果冲突时记录差异并查明原因；不得凭旧文档重画。首版建立当前设计基线，不顺便重新设计。发现现有缺陷时单独记录；不能悄悄修正后声称与原版一致，也不能把未支持的功能补成“当前设计”。

### 2.2 一致性契约

| 维度 | 必须保持一致 | 可以模拟的部分 |
| --- | --- | --- |
| 视觉 | 布局、尺寸、字号、换行、颜色、图标、间距、边框、阴影、截断、层级、滚动和响应式 | 用户名、日期、聊天内容、图片等改用两端相同的合成样本 |
| 本地交互 | hover/focus/disabled、点击、输入、选择、键盘、关闭、焦点恢复、滚动、展开折叠、动画 | 无 |
| 服务驱动交互 | 用户动作、等待状态、允许/禁用的操作、成功/失败反馈、重试和最终页面状态 | 用明确预设结果替代真实服务调用、服务时延及数据持久化 |
| 动态过程 | 思考/工具/正文阶段顺序、停止反馈、内容追加、展开策略、阅读位置保护 | 用确定性脚本替代真实 SSE 和模型输出 |
| 浏览器能力 | 文本选择、DOM 定位、文件选择、裁剪、滚动、复制/下载的实际浏览器行为 | 邮件、上传、分享创建等外部结果；权限失败另提供模拟场景 |

模拟只替换外部结果来源，不能把原来的多步交互缩成一个成功 toast，不能让无效输入或禁用控件在设计稿里可操作。实际网络耗时不要求与生产相同；前端自有的防抖、动画、关闭延时和标亮时长按原版保留。

“一模一样”在固定验收环境中证明。不同操作系统的字体栅格、浏览器权限及手机软键盘不能仅凭桌面截图宣称相同；真机和权限相关证据要单独记录。视觉差异不能以“是 mock”作为豁免理由。

## 3. 范围与非目标

### 3.1 全量盘点要求

实施第一步生成 `design/catalog/coverage.json`，逐项列出页面、入口、组件、状态和用户操作。第 4 节是最低覆盖范围，实施时从实际路由、条件渲染、事件处理器及现有测试中补齐，不是封闭清单。

每个覆盖项至少记录：

- 稳定 ID、名称、分类和适用视口。
- source commit、源文件及组件名；行号只能作辅助，不能是唯一索引。
- scenario ID、进入路径、初始状态、动作序列和预期结果。
- 涉及模拟的部分、原版已知限制。
- Design 对应文件、验证用例及证据路径。
- 状态：未迁移、待验证、已验证、受阻；不能用“页面已存在”表示全部状态完成。

无需穷举所有状态的笛卡尔积，但每个可见分支必须有覆盖；会互相影响的组合必须实测，例如引用＋附件＋模型菜单、流式＋搜索定位、侧栏收起＋账号浮层。

### 3.2 不纳入初版

- Figma 式拖拽编辑器、图层面板、多人实时编辑、账号体系或在线评论系统。
- 真实 API 客户端、JWT 刷新、SSE 重连、数据库、上传协议、邮件投递和模型调用。
- 后端权限、计费、队列与数据一致性的第二套实现。
- 新主题、新产品功能、无依据的 UI 美化或正式前端架构重构。
- 强制单文件 HTML 导出、公共发布平台或浏览器内历史版本构建服务。

保留真实 UI 必需的复杂度，例如 Markdown 渲染、文本选择和滚动协调；“保持轻量”不能成为简化这些效果的理由。

## 4. 首版页面、状态与交互覆盖

### 4.1 认证与公开认证页面

来源：`frontend/src/app/App.tsx`、`frontend/src/auth/`、`VerifyEmailBanner`。

- 登录、注册、忘记密码：模式切换、字段校验、密码可见性（以源码现有能力为准）、提交中、字段错误、表单错误、成功反馈与跳转。
- `/verify-email`：加载、成功、无效/过期或缺少令牌、重发入口、发送中、冷却/失败；已登录与未登录的可见差异。
- `/reset-password`：有效和无效链接、密码校验、提交、成功和失败及返回入口。
- `/confirm-account-deletion`：确认处理、成功、失败与返回入口。
- 未验证提醒 banner、重发反馈；认证恢复和失效引发的可见页面变化。
- 模拟身份与令牌只存在于 Design，不写入正式前端 token store。

### 4.2 聊天工作台与导航

来源：`AppShell`、`Sidebar`、`UserMenu`、`ThreadActions`。

- 空白新会话、已有短/长对话、详情加载/失败、会话不存在或不可访问后的回退。
- 桌面展开侧栏、52px rail、最近会话浮层、移动抽屉、账号菜单；列表空态、加载更多及失败。
- 新建、选择、重命名及取消、删除确认及取消、删除中/失败/完成；不同入口反馈一致。
- 聊天页浮动操作与侧栏行菜单；移动端 bottom sheet；菜单视口夹取、外部点击和 Escape。
- 无聊天页 header；提醒 banner 与浮动操作不遮挡；正文、侧栏滚动区域保持原样。
- 切换会话的草稿和阅读状态遵循现有可观察行为；用内存样本复现，不连接业务存储。

### 4.3 Composer、附件与发送

来源：`Composer`、`AttachmentCard`、附件相关展示和输入逻辑。

- 空输入、单/多行、自动增高、发送可用/禁用、Enter/换行及 IME 规则。
- 模型、思考强度、联网搜索等选择器；可用/不可用能力组合和移动端标签回退。
- 文件选择、拖放或粘贴等源码已有入口；图片/文档卡片、上传进度、处理中、就绪、失败、重试、移除、限制及警告。
- 不兼容模型、视觉依赖会话、发送前附件阻塞等现有提示与守卫。
- 回复引用单独发送、与文字/附件组合、移除及回源；引用背景层和菜单外溢保持原样。
- 提交等待、失败后草稿恢复、成功清空、已发送图片的占位与预览接续。
- 使用仓库内小型合成图片/文档；真实文件只在浏览器本地处理，演示上传不得出网。

### 4.4 消息、富文本和流式

来源：`MessageThread`、`Message`、`StreamingMessage`、`Markdown` 及私有 renderer、`ThinkingBlock`、来源组件。

- 用户气泡、助手正文、消息动作及 hover；编辑/取消/重新提交、重新生成、复制成功/失败。
- 标题、段落、软换行、列表、任务列表、引用、分隔线、链接、数学、代码、宽表格、脚注式来源等源码实际支持的内容。
- 代码语言标签、高亮、复制、HTML fenced code 的隔离预览和切换；表格复制和独立横向滚动。
- 思考 raw/summary、无思考、工具进行中/结果、正文接管、完成、失败、取消、恢复草稿的可见状态。
- 可暂停、继续、重置及单步推进的确定性生成时间线；正常播放时保留原有动效。
- 自动跟随、用户向上阅读、回到底部按钮、sticky Composer、底部渐变、reduced motion。
- 选中文字后的回复引用动作：选择中隐藏、稳定后出现、滚动/关闭清理；只对原版允许的正文区域生效。
- 来源引用 hover/点击、来源面板开关及外链；本地样本保留完整展示内容。

### 4.5 历史会话搜索

来源：`ConversationSearch`、搜索文字定位代码及现有浏览器 fixture。

- 展开侧栏、rail、移动入口；能力关闭时无入口。
- 空输入最近列表、查询、防抖、IME、清除、骨架、结果、空结果、错误、重试、分页及分页失败。
- 鼠标与键盘选择、Enter、Escape、焦点约束、重新打开保留查询与滚动。
- 标题命中、正文命中、引用命中；跨会话与同会话重复定位、失效目标。
- 正文跨富文本节点精确标黄，先滚动再保持 2 秒及淡出 1 秒；流式期间定位不被拉回底部。
- 搜索样本覆盖普通输入，不做只识别一个硬编码词的假搜索；在有限本地数据上复现当前可见匹配、排序和分页规则，不开发搜索服务。

### 4.6 分享与公开页

来源：`ShareDialog`、`MySharesCard`、`SharePage`、`MessageAttachments`。

- 聊天页快捷分享：复用或创建后复制；侧栏分享对话框：有效链接、过期选项、创建、复制、撤销、失败。
- 我的分享列表：加载、空、失败、复制和撤销；撤销后的可见更新。
- `/share/:token`：加载、有效、失效/不存在、读取失败；只读正文、来源、附件、旧/新回复引用和回源。
- 分享创建冻结本地快照，继续修改本地会话不能改变已创建快照的画面。
- 演示链接指向 Design 内对应页面，不含真实 share token；附件使用本地预览/下载资源。
- 真实复制失败不得显示真实成功；模拟成功/拒绝须在设计说明中标明，不能用它证明系统剪贴板成功。

### 4.7 账号与头像

来源：`AccountCard`、`AvatarCropper`、`UserMenu`。

- 账号概览、昵称编辑/保存/失败、邮箱验证提醒与重发。
- 改密、注销申请子视图：返回、输入校验、提交中、错误、成功及后续可见状态。
- 头像选择、裁剪拖动/缩放、取消、确认、处理中、失败和更新；真实本地裁剪反馈，模拟上传。
- 退出登录及账号切换的可见结果；不读取或清理真实账户数据。

### 4.8 模型管理控制台

来源：`ModelAdminPage`、`ModelAdminDashboard`、`ModelAdminEditors`。

- 独立访问密钥门、解锁等待/失败、锁定；无需实际密钥即可进入演示，页面外说明模拟输入。
- 模型、上游、路由列表和现有轨道；空态、刷新、错误提示、目录切换和环境导入确认。
- 新增/编辑表单、校验、保存等待/失败/成功、启停、优先级、能力、思考选项及推理输出选择。
- 当前路由与目录首选的现有区分；不能把信息图替换成简化表格。
- 密钥展示只使用明显的虚构掩码，窄屏保留现有操作入口；不实现实际路由选择或上游调用。

### 4.9 基础组件目录

展示实际使用的 token、字体、图标、按钮各态、输入控件、头像、状态提示、Toast、Modal、ConfirmDialog、BottomSheet、加载反馈。

组件示例必须引用 Design 页面使用的同一份组件。组件目录用于理解和复用，完整页面始终是布局及交互验收主体。

## 5. 用户在设计工程中的操作

### 5.1 固定入口与画布隔离

- 入口提供页面/组件目录、场景名称、当前基线或候选标识、说明、视口选择、重置，以及有需要时的时间线控制。
- 产品画布使用独立 iframe 文档隔离工作台样式；画布具有可单独打开的 URL。纯画布不包含工具栏、说明或演示标记，以便忠实展示和截图。
- iframe 使用真实 CSS 视口宽高；不能用 CSS transform 缩放桌面页冒充移动布局。
- Portal、fixed、sticky、`100dvh`、safe area、媒体查询及 document listener 都以画布文档为准。嵌入预览不能向父工作台 portal。
- clipboard、文件选择、浏览器历史及真机验收使用独立画布入口补验；不能把 iframe 权限差异误判为产品行为。
- 视口预设至少 1440×900、390×844，支持自定义宽高及独立页面随窗口响应。

### 5.2 场景和复现

场景链接编码设计版本/候选 ID、页面 ID、scenario ID；刷新直接恢复场景初态。产品内部会话导航由画布内独立路由处理，不覆盖父级场景入口。

每个场景既能直接打开，也能从真实产品入口操作到达。不能用场景下拉菜单代替本应可点击的菜单/弹窗。

重置清理本场景的输入、结果、选区、弹层、滚动、计时器、播放阶段和临时资源；切换场景后旧异步回调不能写入新场景。默认数据在内存中，若某种刷新恢复是产品可见要求，用 Design 独立命名空间的会话存储演示，并让重置可清除。

### 5.3 说明和候选比较

说明记录：用途、入口、布局约束、关键操作、键盘/移动行为、模拟范围、来源文件、设计状态和关联需求。

首版支持 current 与 candidate 在同一个固定视口中切换，便于比较而不改变画布尺寸。无需实现滑动 diff、在线批注或所见即所得编辑器。

## 6. 技术方案与保持轻量的边界

### 6.1 独立 React + TypeScript + Vite 包

- 根目录 `design/` 独立 `package.json` 和 `pnpm-lock.yaml`；只使用 pnpm，不引入 npm/yarn lockfile，不为此改造仓库为 monorepo。
- 采用与源前端一致的 React、Tailwind v4、图标、Markdown/KaTeX 等必需版本，锁定实际解析版本；首轮迁移不升级依赖。
- 提供 `dev`、`build`、`preview`、`lint`、`typecheck`、`test`、`test:visual`、`test:parity`、`check:boundaries` 脚本。
- 开发端口默认 5180，preview 默认 4180，冲突时报错，不静默换端口；不读取 `VITE_API_BASE_URL` 或根目录 `.env`。
- 依赖安装后启动与浏览不需要 backend；字体、图标、图片和样本资源随包提供，保留现有字体栈及合法授权信息。
- 正式 `frontend/` 的入口、构建及部署不包含 Design。

建议结构如下；可按代码规模合并小文件，不能为目录形式引入空抽象：

```text
design/
  README.md
  package.json
  pnpm-lock.yaml
  index.html
  canvas.html
  vite.config.ts
  src/
    workbench/             # 目录、场景选择、说明、比较和播放控制
    canvas/                # 产品画布入口和路由装配
    ui/                    # Design 自有展示组件与局部交互
    pages/                 # 完整产品页面
    styles/                # 独立 token、全局样式、字体
    scenarios/             # 注册表、固定样本、有限交互脚本
    runtime/               # 重置、调度、浏览器能力的少量公共代码
    proposals/             # 活跃候选的局部变体
  public/assets/           # 合成媒体和必要字体
  catalog/
    coverage.json          # 全量来源/场景/证据对应表
    baseline.json          # source commit、环境和验收状态
  tests/
    interaction/
    visual/
    parity/                # 调度原版与 Design 的同场景比较
  references/              # 固定的原版截图与几何基准
  approvals/               # 用户确认版本和范围的记录
  output/                  # 忽略提交的诊断结果、diff、构建证据
```

### 6.2 首次提取与后续独立维护

复制源前端的必要 JSX、class、token、图标、资源和纯展示算法，随后移除业务依赖。Design 不在运行、构建或类型检查时 import `frontend/src`、其 CSS、token store、测试 harness 或 API 类型；也不以符号链接绕过隔离。

可以在首次迁移时复制必要的展示类型或格式化/定位函数，并记录来源。此后它们由 Design 独立维护，不建立自动覆盖同步任务，不要求抽出一个供生产和设计共同依赖的新 UI 包。

不得整包复制 `AppProvider`、API factory、token refresh、Run reducer、上传轮询和业务 hooks，再藏到 mock 开关后。对于含副作用的组件，保留其 DOM 和样式结构，把外部调用换成小范围显式事件回调。只做迁移必需拆分，不改写正式前端。

允许保留原样的 UI 算法，例如 Markdown renderer、裁剪、Selection、来源定位和滚动跟随。拆分后必须用原版对照证明行为未变。

### 6.3 场景数据与有限交互

用一个小的场景注册表组织页面。每个场景包含 ID、页面、数据、初态、可选时间线、说明和验证关联。优先 props、局部 state 和必要的场景级 Context；不引入通用全局业务 store。

场景只管理用户能观察到的有限状态：例如发送、出现用户消息、追加预设回复、停止、重试。需要保存会话列表/分享快照等本地结果时使用小型内存对象；不实现 API envelope、JWT、队列、租约和网络恢复协议。

普通交互应支持样本范围内的连续操作，不能只有一次有效。使用稳定 ID、固定日期、固定样本和可控时钟；演示节奏可配置，复现截图时可停在准确阶段。

### 6.4 隔离验证

- 边界检查扫描跨目录 import、动态 import、CSS import、软链接和构建资源，拒绝生产代码依赖。
- 浏览器测试阻止产品 API、远程图片、字体和服务调用；允许 Design 静态资源及开发 HMR。点击外链的显式用户导航单独验收，不作为启动所需网络。
- 不注册生产 service worker，不读写生产存储 key，不携带真实凭据。演示身份、邮箱、文件与密钥均为合成数据。
- 不新增 mock server/service worker 框架；如果某展示算法需要异步结果，直接注入本地 Promise 回调。

## 7. 不能丢失的布局与交互约束

从当前源代码提取并在浏览器验证，以下为已知高风险项：

- 根字号 15px、Tailwind spacing 4px；不能把已有 px 随意替换成 rem。
- 桌面侧栏 280px/52px 的固定画布裁切与过渡；收起时隐藏区域退出交互，账号头像锚点不移动，rail 浮层不被裁切。
- 助手内容列及 Composer 768px；桌面 gutter 与移动 16px gutter 对齐，share 有自身 containing block。
- Composer 位于真实消息滚动容器内的 sticky 底部层；保留渐变 mask、背景透明度和 136px 回到底部阈值，不改为固定悬浮截图。
- 思考/工具标题跨 delta 保持相同垂直几何，不能根据流式状态改变已渲染锚点的高度、padding、margin-top。
- 回复引用独立宽度、三行限制、换行规则、hover、前导背景、回源标注和 Selection 时序。
- 搜索无全局暗色遮罩、桌面相对完整视口定位、移动全屏、准确 DOM Range 高亮。
- 宽代码/表格内部滚动，不导致页面横向溢出；HTML 代码预览保持原隔离规则。
- Modal/BottomSheet/菜单维持原有焦点、Escape、外部点击、触摸、遮挡与 reduced-motion 行为。

这些数值不是重新设计规范；若最终 source commit 已改变，更新基线记录与对应断言后再迁移。

## 8. 一致性验收方案

### 8.1 原版与 Design 分开渲染

原版基准页必须实际使用指定提交的生产组件和样式，不能拿 Design 的组件给自己当参照。现有 `frontend/tests/visual/` 可作为原版入口的基础，但它们覆盖有限，不能代替整个产品。

按覆盖清单补充只用于验证的原版场景装配，优先复用 `AppProvider` 已有 service 注入能力；仅原版 harness 可以依赖 `frontend/src/test`。其他页面用适合原版的测试数据注入，不要求真实账户、模型或业务写入。必要的原版 harness 文件进入 `frontend/tests/`，不进入生产构建，不为此重构生产 UI。

原版与 Design 使用内容一致的 fixture：由测试侧转换或复制纯数据并校验 hash，不能共享展示代码。原版测试侧可依赖其自己的 DTO；Design 不需要理解 API 契约。

若实施跨多个 source commit，固定原版截图、依赖与源文件 hash；必要时使用 `git archive` 到临时参考目录运行指定版本，不切换/覆盖工作区，不使用 worktree。不能用当前不断变化的 HEAD 冒充冻结基线。

### 8.2 固定环境与视觉比较

记录 OS、Chrome/Chromium 版本、字体、DPR、locale、时区、主题、视口、滚动条形式、样本 hash、source/design commit 和动画阶段。

- 主验收：同机同浏览器两份页面，浅色、DPR 1、1440×900 与 390×844。
- 补验：760px 断点两侧 759/760/761px、短视口及宽桌面；页面在任意可用宽度仍遵循原响应式规则。
- 每个页面默认状态、重要弹层与会影响结构的关键状态都有配对截图；长页面同时保留 viewport 与 full-page 证据。
- 等待字体/图片就绪和布局稳定，冻结日期与随机数据。仅对确实不可控且不属于验收对象的区域记录 mask；不能遮住待核对的 UI。
- 相同环境以像素零差异为默认目标。抗锯齿等差异逐项定位、记录原因并人工审阅，禁止用大范围容差掩盖布局偏差。
- 关键 rect 与 computed-style 单独断言，尺寸/坐标默认容差不超过 1 CSS px；行数、截断、可见性、颜色、字体与层级按原版核对。
- 现有 Windows golden 不能直接作为 macOS 像素基准；CI 在固定环境建立对应基准，不自动覆盖旧的生产 golden。

### 8.3 交互与动态证据

同一操作脚本分别操作原版和 Design，对照每一步的可见状态、焦点、可用动作、导航、滚动和错误反馈。全部覆盖项必须有自动化用例或明确的人工操作记录，不能只记录“点过了”。

重点脚本包括：登录/公开认证、会话 CRUD、模型选择与输入、附件、发送/失败/停止、编辑重发、引用及回源、搜索分页定位、两种分享入口、账号/裁剪、模型管理表单。

动画单独在正常 motion 下采样，静态截图可以 reduced motion；流式和侧栏时间线记录关键帧与真实 Chrome 几何数据。参照思考标题交接中的测量方法，jsdom 测试不作为几何证明。

手机视口验证不等同实体手机。对软键盘、safe area、触摸选择及 iOS 剪贴板等平台行为，记录原版与 Design 的真机结果；没有设备时明确受阻项，不能宣布全平台一致。已有源前端未完成的平台验证应保留其已知限制，不扩大本次承诺。

### 8.4 证据与通过规则

`coverage.json` 的每项关联：原版图、Design 图、diff、几何数据或交互报告。诊断输出在 `output/`；固定原版参考及必要验收图进入版本控制，避免引用会失效的临时路径。

缺少页面、可见状态、交互或存在未解释的视觉差异都阻止首版完成。无法执行的检查标记受阻，列出环境和补验命令，不能写成通过。用户批准明确偏差后记录例外及影响；不得由 agent 自行把偏差当作批准。

## 9. 新 UI 需求的工作流

### 9.1 当前设计与候选设计

- `current` 指向最近已确认的设计，候选有稳定 proposal ID、基准版本、关联需求、受影响页面和状态。
- 新候选复用 Design 内的页面和组件；通过局部变体组合到完整页面，不能重画周围 UI 或复制整套工程。
- 候选不能直接修改 current 共用实现而使 current 跟着变化。候选局部变化放在变体里；涉及全局 token 时，在候选画布文档内覆盖，不能污染当前版本。
- 比较入口在相同场景、视口和样本下切换 current/candidate。源码提供准确的 token、组件与文件位置，不要求用户逐项描述 CSS。

### 9.2 确认、实现和同步

1. 需求说明确定行为；Design 表达完整页面及交互。
2. 用户明确确认后，在 `approvals/` 保存 proposal ID、确认范围、需求链接、设计 commit、scene IDs、截图和例外。agent 不自行宣称设计已获批准。
3. 正式前端按固定设计版本实施；可复用展示代码，但不得迁入 Design 控制台、场景数据和演示结果逻辑。
4. 实现过程中发现必须修改设计时，更新候选与受影响确认记录；未涉及部分不重复确认。
5. 对照已确认版本完成前端验收，记录实现 commit。再将选定方案提升为 current，清理活跃目录中已结束的候选变体；历史由 Git 和确认记录保留。

批准记录分开保存 `designStatus`（draft/approved/superseded）与 `implementationStatus`（not-started/in-progress/verified），避免设计已确认被误读为产品已上线。

历史查看首版通过固定 Git commit 和截图完成，不在浏览器里提供任意历史构建。跨版本不会自动同步：设计变更需要实施记录；生产紧急 UI 修复必须回补 Design 并留下对应关系。

### 9.3 Ready 的实际演练

交付前用一个不改变产品需求的演练候选验证：从现有完整页面建立一个局部变体 → 入口可切换比较 → 修改变体后 current 的截图/几何不变 → 能生成包含版本和场景的待确认记录 → 清理演练。

演练不得冒充用户批准或引入真实新功能。提交可复用的最小候选示例/说明，让下一个需求无需重新建立页面外壳、数据系统或版本机制即可开始。

## 10. 实施阶段与交付物

按顺序实施，每阶段可以逐页面完成，但首版总范围不缩减。

| 阶段 | 工作 | 完成证据 |
| --- | --- | --- |
| 1. 固定来源 | 核对 source commit、路由、组件、交互分支、能力开关与已有测试；建立覆盖清单 | 每个页面/状态有来源，原版已知限制可追踪 |
| 2. 采集原版 | 建立缺失的原版 harness、统一样本与环境，保存截图和关键交互 | 原版各场景可独立复现，无真实业务写入 |
| 3. 独立骨架 | 建立包、双入口、样式隔离、场景注册/重置、边界检查 | 独立安装、启动、构建，纯画布可直达 |
| 4. 基础与页面 | 提取 token/控件；迁移认证、聊天、搜索、分享、账号、模型管理全部表面 | 覆盖项逐个关联到可打开的 Design 场景 |
| 5. 交互补齐 | 有限模拟结果、连续操作、动态播放、键盘/移动、失败/重试 | 同操作脚本的原版/Design 状态对照通过 |
| 6. 一致性收敛 | 桌面/移动配对图、几何、动画、浏览器能力检查，修复差异 | 无遗漏和未解释偏差，测试/构建通过 |
| 7. 新需求就绪 | current/candidate、说明/确认记录、演练、使用文档、CI | 可从现有页面直接开展新的 UI 需求 |
| 8. 初版交付 | 汇总覆盖报告、证据、启动方式、限制和固定基线 | 第 12 节逐项通过，用户可打开完整设计册 |

阶段 4 内优先完成基础和聊天布局是实施顺序，不代表只交付聊天页。不能在阶段 3 的空壳或阶段 4 的局部截图时宣布 ready。

## 11. 检查、文档与 CI

以下脚本已由 `design/` 提供：

```bash
pnpm --dir design install --frozen-lockfile
pnpm --dir design dev
pnpm --dir design lint
pnpm --dir design typecheck
pnpm --dir design test --run
pnpm --dir design check:boundaries
pnpm --dir design test:visual
pnpm --dir design test:parity
pnpm --dir design build
pnpm --dir design preview
```

`test:parity` 自动管理两端参考服务器、端口和测试侧样本，缺失参考依赖时明确报错，不默默跳过。允许要求安装 `frontend/` 依赖用于对照，但 Design 自身安装/启动/构建不能依赖它。测试 README 说明浏览器安装、基准环境与参考版本准备。

- 增加独立 Design CI job，安装其冻结 lockfile，运行静态检查、边界检查、必要交互、固定环境视觉与 build；配对验收所需原版依赖单独安装。
- 视觉基线更新必须经过明确审阅，CI 失败不自动更新 snapshots。
- 新增原版 harness 或改动前端测试配置时，运行现有 `frontend/` 的 lint、typecheck、Vitest、build 和受影响的浏览器检查；不改动无关业务代码。
- `design/README.md` 提供中文使用与维护说明；`docs/` 中补充中文架构/验收交接，`docs/README.md` 用英文加入路由指引。
- 前端 UI 工作的文档导航需要指向本规格和实际确认记录，并区分设计行为与 API/领域契约的权威来源；Design 不覆盖后端 ADR。
- 原有单需求 HTML 保留历史，不迁为 current，不让用户误入旧稿；从其说明页链接到新入口并注明适用范围。
