## 1. 问题与目标

用户记得曾经讨论过的标题、关键词或一句话，但无法确定它属于哪个会话、发生在什么时候。当前侧栏以时间顺序分页列出会话，依赖逐条打开寻找；长会话即使打开，也需要再次查找相关消息。

首版提供完整路径：

> 打开侧栏搜索 → 输入记得的文字 → 根据标题和命中片段确认目标 → 打开会话并定位、标亮相关文字 → 继续阅读或对话。

可观察的成功标准：

1. 用户可以从展开侧栏、桌面收起侧栏和移动端侧栏进入搜索。
2. 标题或正文包含查询文字的可见历史会话能被找到，包括尚未加载到侧栏的旧会话。
3. 搜索结果能说明命中原因，同一会话不因多条消息命中而重复占据列表。
4. 正文结果打开后能看到对应消息和短暂淡黄色标记，无须再手动翻找。
5. 搜索和跳转保留既有草稿、Run 生命周期、权限和消息可见性规则。

## 2. 参考观察与本项目决策

### 2.1 已观察到的 ChatGPT 行为

观察环境为 2026-09-05 用户当前账户的 Chrome 桌面版；未实测手机端，不推断其他账户版本。

| 环节 | 实测行为 |
| --- | --- |
| 入口 | 侧栏顶部放大镜 |
| 容器 | 居中白色圆角弹窗、细边框、阴影，原会话仍在背景中可见 |
| 空输入 | 显示“上次打开”和“最近聊天” |
| 查询 | 自动聚焦，输入后自动搜索，提供清除和关闭 |
| 结果 | 气泡图标、标题、一行截断片段、右侧日期；关键词加粗，选中行浅灰背景 |
| 键盘 | 默认选择第一条，方向键切换，Enter 打开，Escape 关闭 |
| 状态 | 加载骨架；无结果提示；再次打开保留上次查询和筛选 |
| 正文跳转 | 关闭搜索，进入对应消息；目标消息中的命中文字出现淡黄色背景，之后消失 |

排序观察需保留限制：

- 搜索“春望”时，正文命中的“推荐唐诗”排在标题命中的“介绍春望”前面，顺序与侧栏最近会话顺序一致。
- 搜索 `SKILL`，加载完成后的连续结果日期出现 8 月 15 日、8 月 19 日、8 月 16 日、8 月 31 日、8 月 21 日，界面顺序并非严格按右侧日期倒序。
- 未验证内部排序字段、相关性权重或展示日期含义。因此不能声称 ChatGPT 使用纯时间排序，也不能声称标题或正文固定优先。

高亮观察需修正第一次报告：第二轮在点击后立即截图，明确捕捉到目标回复中的“春望”两字标黄，随后恢复正常；同屏另一条消息里的相同文字未一起标亮。第一次未观察到是遗漏短暂效果，不能作为“不支持高亮”的依据。未精确测量 ChatGPT 的保持时间、淡出时长或所有富文本场景。

### 2.2 iChat 采用的规则

- 借鉴搜索弹窗、紧凑结果、键盘选择、查询保留和定位后短暂标黄。
- 只提供对话搜索，移除类型标签栏和来源筛选。
- 标题与正文平等参与匹配，统一按**会话最近更新时间倒序**，不额外给标题命中加权。
- 空输入首版只显示最近会话，不增加独立“上次打开”记录。
- 高亮保持 2 秒、用 1 秒淡出；这是本项目默认值，不是 ChatGPT 的精确测量值。
- 移动端使用全屏搜索容器；这是本项目设计，不是本轮竞品实测结论。

## 3. 搜索范围

| 数据 | 首版范围与语义 |
| --- | --- |
| 会话标题 | 当前标题，包括自动生成和手动重命名后的标题；旧标题不保留为搜索别名 |
| 用户消息 | 已持久化、当前可见分支的提示文字 |
| 助手消息 | 已物化、当前可见分支的回复正文，包括正文代码、列表、表格和链接显示文字 |
| 回复引用 | 当前可见用户消息上已发送的引用文字快照；结果定位到承载引用的用户消息，不跳到引用来源 |
| 思考过程、推理摘要 | 不搜索 |
| 工具调用、网页来源面板、Run transcript | 不搜索 |
| 附件 | 不搜索附件名、文档派生文本、图片 OCR、附件卡片内部数据 |
| 未发送草稿、临时流式正文 | 不搜索；助手成功物化后参与后续查询 |
| 已删除会话 | 不搜索，包括仍在恢复期的数据；恢复后按正常可见性参与搜索 |
| 归档消息 | 编辑或重新生成前的旧分支不搜索 |
| 公开分享、其他用户会话 | 不搜索；搜索仅面向当前登录账户 |

搜索覆盖完整可见历史，不能限制在侧栏已经加载的 30 条或 rail 最近 10 条。尚未激活、不会出现在正常历史列表中的会话不参与搜索。没有标题的可见会话仍可由正文命中，展示现有无标题回退文案。

“文档搜索不支持”指不建立文件内容搜索能力；用户直接发在消息正文里的文本仍属于正文范围。

## 4. 匹配、排序与结果选择

### 4.1 查询语义

首版采用连续文字匹配，不进行语义检索、同义词扩展、纠错、拼音或繁简转换。

- 去除查询首尾空白，英文 ASCII 字母忽略大小写；中文按文字本身匹配。
- 查询至少 1 个、最多 200 个 Unicode 码点；超长输入显示校验提示，不静默截断。
- 将查询和可搜索普通文本中的连续空白折叠为一个空格，使复制带换行的短句可匹配；折叠仅用于查询表示，不改原始消息或代码缩进。
- 多个词按一个连续短语处理。例如 `数据库 连接` 不代表两个词可分散在不同消息中命中；不会跨消息、跨标题与正文、跨引用与提示文字拼接匹配。
- `%`、`_`、引号等均为普通字符，不解释为 SQL 通配符或高级搜索语法。
- 用户消息按原始显示文字搜索；助手 Markdown 按正文文本表示搜索，去掉格式标记、保留代码内容和链接显示文字，不因隐藏链接地址、HTML 属性或代码语言标签单独命中。
- 数学公式的 TeX 指令检索、渲染符号与公式源码互搜不纳入首版承诺；包含公式的消息，其普通文字仍可搜索。

服务端的匹配、片段生成和浏览器目标定位必须使用一致的文字语义。不能一处对 Markdown 源码搜索，另一处对可见文字猜测位置。正文文本表示及原文位置映射的实现方式见第 9 节待验证项。

### 4.2 会话排序

1. 标题或任意范围内消息命中即可入选。
2. 每个会话只返回一条结果。
3. 按 `Conversation.updated_at DESC` 排序；时间相同时沿用现有会话列表的内部 `id DESC` 稳定顺序，内部 ID 不暴露到 API。
4. 排序时间属于整段会话，不是命中消息时间，也不是用户打开搜索或阅读会话的时间。
5. 打开、搜索和定位是只读操作，不能更新会话时间或将结果置顶。
6. 沿用当前更新时间语义，包括现有重命名等操作带来的时间变化；不新增“最后聊天时间”字段。

例：会话 A 昨天的正文包含“数据库”，今天有新的对话活动；会话 B 标题包含“数据库”，最后更新在前天。A 排在 B 前面。即使 A 的命中消息本身比 B 更早，也不改变这个顺序。

### 4.3 同一会话的代表命中

- 有消息命中时，选择当前分支 `position` 最大的命中消息，即最近的一条命中消息。
- 同一用户消息的提示文字和回复引用均命中时，优先提示文字；仅引用命中则使用引用。
- 在选定文本内取第一次连续匹配作为代表位置。片段围绕该位置截取，保留前后上下文。
- 标题与消息同时命中时，标题加粗对应文字，第二行展示消息片段，点击进入该消息。
- 只有标题命中时，展示标题与日期；不伪造正文命中片段，点击沿用普通进入会话行为。
- 首版不展示命中总数、不展开会话内命中列表，不提供上一个／下一个命中控件。

上述选择保证“结果里看到的片段”与“进入后定位的位置”一致。后续若改变代表消息选择策略，需同时更新验收例，不能让前后端各自决定。

## 5. 入口与界面

### 5.1 侧栏入口

- 入口位置采用当前已确认样稿：搜索紧接在“新建对话”下方，作为独立的一行。
- 桌面展开态从上到下为“新建对话 → 搜索对话 → 最近对话列表”；搜索行显示放大镜与“搜索对话”标签。
- 桌面 rail 从上到下为“新建对话图标 → 搜索放大镜 → 最近对话图标”；保留既有最近会话入口。
- 移动侧栏抽屉沿用展开态顺序，“搜索对话”位于“新建对话”下方、最近对话列表上方；点击后关闭抽屉并进入搜索。
- 收起态提供 tooltip 与可访问名称。遵守既有固定侧栏画布、宽度裁切与控件几何约束，不为加入搜索重做侧栏动效。

### 5.2 桌面弹窗

- 桌面面板以整个浏览器视口水平居中；垂直方向在几何居中基础上上移卡片自身高度的 10%（默认 460px 高时上移 46px），不扣除顶部工具栏或侧栏占用的空间。该位置参考 2026-09-05 Chrome 中 ChatGPT 搜索卡片截图：约 1294px 高视口内，460px 高卡片中心约在 y=601px，比视口中心高约 46px；这是视觉采样后的样稿实现选择，不代表已确认竞品 CSS 公式。短视口下限制卡片高度，保留顶部至少 24px 间距。中央固定尺寸感的面板，宽度上限默认 720 CSS px，两侧至少 24px 视口间距；最大高度受视口限制。
- 默认面板高度约 460px，输入区固定，结果区独立滚动。结果为零或很少时不突然收缩弹窗。
- 采用项目现有背景、字体、边框、圆角和阴影 token；不复制竞品私有 DOM/class，也不将截图尺寸当作已测量的 CSS 参数。
- 顶部包含输入框、非空时的清除动作与关闭按钮，不另加重复大标题、提交按钮或类型筛选栏。
- 打开后输入框自动聚焦；背景保持原会话状态，但退出交互与键盘焦点循环。
- 不添加全局变暗或模糊遮罩，仅保留搜索卡片自身的边框和阴影。点击弹窗外部、关闭按钮或 Escape 关闭。取消搜索时恢复原阅读位置及触发器焦点。

### 5.3 移动端

- 沿用现有 760px 移动断点，搜索占满可用视口，顶部输入与关闭入口固定，结果独立滚动。
- 使用动态视口高度及 safe area；软键盘弹出后最后一条结果仍可滚动到达，页面不产生双重滚动。
- 搜索入口、关闭和清除的有效触控区域至少 44×44 CSS px。
- 成功打开结果后关闭搜索并收起软键盘；关闭搜索回到原聊天页，侧栏保持关闭。

### 5.4 结果行

结果行包含气泡图标、单行标题、单行命中片段和右侧更新时间。标题与片段超宽时省略，日期不挤压到不可读。标题单独命中时保留行高，不重复标题充当摘要。

- 标题使用主要文字颜色，片段和日期使用次要颜色。
- 查询命中文字加粗，选中或 hover 使用浅色圆角背景；此处不使用正文跳转的淡黄色标记。
- 片段不渲染完整 Markdown、可点击链接或代码工具栏，不显示内部标识。
- 日期使用与界面一致的本地化时间格式，跨年应可区分年份；可访问说明或 tooltip 提供完整更新时间。
- 首版结果行只有打开动作，不增加分享、删除、重命名菜单。

## 6. 输入、加载和会话内状态

| 状态 | 触发与展示 |
| --- | --- |
| 空输入 | 显示最多 10 条最近可见会话，仅标题；无历史时显示对应空态 |
| 输入中 | 最后一次有效输入后 250ms 发起查询；中文 IME composition 期间不搜索拼音中间态 |
| 首次加载 | 保持容器几何，结果区显示骨架 |
| 查询成功 | 展示第一页，默认选择第一条；无匹配时显示无结果提示 |
| 更换查询 | 重置分页和选择，旧查询结果不再可点击，迟到响应不得覆盖新查询 |
| 加载更多 | 接近底部获取下一页，底部显示局部加载状态；已有结果仍可用 |
| 查询失败 | 展示失败和重试；失败不能显示为无结果 |
| 加载更多失败 | 保留已有结果，在底部提供重试同一页入口 |
| 清除 | 取消当前查询，恢复空输入状态，焦点留在输入框 |
| 关闭 | 取消未完成请求及计时器，在当前登录会话内保留查询、已展示结果和列表位置 |

分页默认每页 30 个会话，服务端返回是否还有下一页或等价游标，不要求昂贵的命中总数。具体分页协议在实施设计中定稿；必须保证数据不变时遍历完整、不重复。并发更新允许查询视图变化，不承诺跨请求数据库快照；前端按会话 ID 去重，重新查询从第一页开始。

再次打开时恢复查询、选择及滚动位置，并验证数据新鲜度。结果未变化时不重置位置；目标结果已删除时移除并保留邻近位置。刷新页面后可以回到空输入，不将搜索词和片段写入 localStorage。

退出登录、认证失效或切换账户必须清空查询、结果、分页和待跳转状态，并取消请求，迟到响应不得恢复上一账户内容。

键盘规则：

- ↑↓在结果间移动，自动将选中行滚入结果视口，不循环越界。
- Enter 打开当前选中结果；没有可用结果时不产生动作。
- 输入法候选确认的 Enter 不触发结果打开；composition 结束后才处理正常搜索键盘行为。
- Escape 关闭搜索，Tab 在弹窗有效控件间循环；清除与关闭各有独立名称。
- 使用合适的 dialog、combobox/listbox 或等价可访问模式，读屏能感知加载、无结果和当前选择；不在每次按键时朗读完整结果。
- 首版不增加全局快捷键，避免未经讨论覆盖浏览器或应用已有绑定。

## 7. 点击结果、定位与高亮

### 7.1 跳转流程

1. 记录结果携带的会话 ID、消息 ID、命中字段与代表位置；阻止重复点击并关闭弹窗。
2. 跨会话时走现有 `/c/:publicId` 导航及详情加载、Run 恢复流程；同一会话也必须执行新的定位意图，不能因 selectedId 未变而跳过。
3. 等待目标会话的权威详情和目标消息正文挂载，再解析范围。
4. 在实际 `.thread-region` 滚动容器内定位，使命中文字及适量上下文可见；不能只滚到整条长回复顶部，也不能滚动整个 document。
5. 滚动稳定后标黄，完成后清理定位意图。只命中标题的结果没有消息定位意图。

首版 URL 沿用会话路由，搜索词及精确位置只放在临时导航状态中；不增加可分享的搜索深链，不要求刷新重演标记。结果可见性由服务端重新校验，临时导航状态不授予权限。

### 7.2 标记粒度与时间线

- 只标亮代表命中的文字范围，不给整条回复或整个段落铺黄色背景，也不标亮其他消息里的同词。
- 一个连续匹配跨越 strong、emphasis、链接文字或代码高亮 span 时，视觉上仍标出同一段文字。
- 引用命中标亮用户消息中的引用快照。若代表位置在三行截断区之外，导航期间临时展开该引用以显示命中位置；用户离开该会话或再次导航时恢复默认截断。
- 先滚动，后开始 2 秒保持；随后用 1 秒淡出并完全移除标记。布局未稳定的时间不能消耗保持时长。
- 保留文字原本的字体、字重、行高、换行、代码样式与复制内容。高亮不能借用原生 Selection，以免触发回复引用浮层。
- 减少动态效果偏好下立即定位，保持 2 秒后直接移除，不使用平滑滚动或淡出。
- 新定位、会话切换、退出登录、卸载时取消上一套滚动/标记任务。用户主动滚动时停止自动追赶，不能把用户反复拉回目标。

既有回复引用来源跳转按 Markdown 语义节点标黄；本功能按命中文字标黄，两者粒度不同。可以复用滚动稳定检测、计时与清理机制，但不能直接沿用来源节点高亮替代本需求。

### 7.3 与草稿、流式和失败的关系

- 打开搜索不发送消息、不停止服务端 Run、不清空 Composer、附件或回复引用草稿。
- 打开结果只执行既有会话切换，旧会话草稿按现有机制保存；不得把旧草稿带入目标会话。
- 搜索期间原会话可继续流式生成；定位到历史内容后保持阅读位置，不被后续 delta、详情重拉或终态替换强制拉到底部。
- 初始化滚到底部与搜索定位必须协调优先级，不能先定位成功又被初始化效果覆盖。
- 搜索读取到结果后，会话可能被删除或消息被归档。无权访问和不存在沿用统一处理，不透露其他账户数据。
- 会话不可访问时显示 `无法打开这段对话，请重新搜索后再试。`，保留搜索卡片与当前会话，移除已失效结果，用户可继续寻找其他结果。
- 会话仍可访问但消息不存在、字段改变或范围不再匹配时，提示 `原搜索内容已变化，已打开对应对话。`。消息仍存在则只滚到该消息，不在其他消息中猜测替代命中；消息不存在则沿用普通会话打开位置。
- 详情网络失败显示失败和重试，不报告定位成功。取消或被新导航替代的请求不弹出过期错误。

## 8. 提示文案

根据本需求的界面评审结论，所有界面文字使用中文，包括按钮、占位、日期、错误提示和可访问标签；品牌名与代码原文保留原样。

| 用途 | 默认文案 |
| --- | --- |
| 入口 / 可访问标题 | `搜索对话` |
| 输入占位 | `搜索历史对话` |
| 最近列表 | `最近对话` |
| 清除 / 关闭 | `清空搜索` / `关闭搜索` |
| 无历史 / 无结果 | `还没有历史对话` / `未找到相关对话` |
| 搜索失败 | `搜索失败，请重试`；辅助说明：`请检查网络连接后再试` |
| 加载更多失败 | `加载失败，点击重试` |
| 重试 | `重试` |
| 查询过长 | `搜索内容不能超过 200 个字符` |

界面评审补充：

- 无结果、无历史与搜索失败时，提示图标、文字及重试按钮作为整体，在输入区下方的空白结果区域水平和垂直居中。
- 搜索结果气泡复用现有侧栏 rail 的 `Icons.Chats` 路径，显示尺寸为 20px，沿用 ChatGPT 的轻量气泡比例。
- 仅“点击后结果失效”的浮动提示采用项目 error toast 样式（圆形感叹号、浅红背景、红色边框和文字）。搜索失败保持灰色图标、文字与重试按钮；加载更多失败保持普通文字与重试按钮。
- 搜索卡片的滚动条滑块与结果 hover 背景共用颜色，样稿为 `#ededed`。

## 9. 实施边界与待验证项

### 9.1 现有入口与职责

- `frontend/src/conversations/Sidebar.tsx`：搜索触发入口，继续承担导航展示。
- `frontend/src/conversations/`：搜索业务状态与请求编排，不把结果覆盖到普通会话索引中。
- `frontend/src/api/conversations.ts` 与 API 类型：搜索 wire contract，经现有 ApiClient 认证与刷新逻辑调用。
- `frontend/src/app/AppShell.tsx`：搜索与路由、详情加载、Run 恢复、滚动容器的装配。
- `frontend/src/messages/`：正文目标解析、命中文字标记及清理；普通搜索结果不复制完整消息渲染器。
- `app/api/v1/conversations.py`、`app/schemas/conversations.py`、`app/services/conversations/`：受保护的历史查询契约与业务规则。
- `app/search/` 当前是外部联网搜索基础设施，不读数据库；历史会话查询不放入该模块，也不调用 LLM/provider。

沿用当前可见性条件：会话归当前 user、未删除且已激活；消息 `archived_at IS NULL`。搜索从 PostgreSQL 事实中取得范围，不查询 Run transcript 作为消息正文的替代。

### 9.2 建议的数据契约

建议新增独立的受保护会话搜索端点，而不是向前端拉取全部消息后本地搜索。路径、分页与字段命名在实施设计中冻结，最低契约包含：

- 请求：查询文字、页面大小和分页位置；身份由认证上下文确定，不能信任客户端传入 owner。
- 每条结果：会话 public ID、当前标题、会话更新时间、标题命中信息。
- 消息命中：消息 public ID、命中字段（正文或回复引用）、纯文本片段、片段内高亮范围，以及足以恢复代表位置的版本化定位信息。
- 标题单独命中：消息命中字段为空，不伪造消息 ID。
- 分页：下一页状态；响应仍使用 `{"data": ...}` envelope。
- 范围明确采用统一编码、半开区间和文本版本；不能把 Python 码点偏移直接当成 JavaScript UTF-16 偏移使用，尤其需覆盖 emoji。

若采用 `/conversations/search`，必须避免被现有 `/{conversation_id}` 动态路由当作 UUID 解析。查询日志、错误及监控不记录完整搜索词或正文片段；接口不返回内部 ID、transcript 或附件私有定位信息。

### 9.3 实施前必须完成的技术验证

1. **正文文本投影与位置映射**：验证 Markdown 去格式、代码、链接文字、空白折叠、emoji 与引用的统一匹配语义。投影必须可从原始事实重建，不能改写 `Message.content`。
2. **查询与索引方案**：用真实 PostgreSQL 查询计划与代表数据集比较可行方案，覆盖短中文、常见词、无结果和长代码。不得未经测量承诺全表模糊查询能满足规模需求，也不默认引入独立搜索服务或向量索引。
3. **数据新鲜度**：若需要派生搜索字段或索引，定义存量回填、新消息、重命名、归档、删除及恢复的更新方式；正常提交后的下一次新查询应反映当前事实，不能把旧分支继续返回给用户。
4. **导航竞争**：验证目标消息挂载、代码渲染、附件布局、初始化置底、Run 恢复与搜索定位的先后次序。
5. **性能目标**：默认以每账户 1,000 个会话、20,000 条消息的测试集，首屏搜索 API p95 ≤ 500ms 作为初始目标（不含网络、前端 250ms 防抖与首次回填）；实施时记录消息长度分布、硬件、并发量及冷暖缓存。未完成基准前不声称性能已达标，目标调整需在规格中说明依据。

2026-09-05 已在当前工作区实现。迁移、回填、真实 API 与浏览器验证及本地启动方法见[实施交接](../handover/2026-09-05-conversation-search.md)。未进行生产部署。

## 10. 验收矩阵

| 编号 | 场景 | 预期与验证方式 |
| --- | --- | --- |
| S01 | 侧栏展开、rail、移动抽屉 | 搜索入口均紧接新建对话下方，位于最近对话入口或列表上方；三个入口可用，真实浏览器核对布局、触控和焦点 |
| S02 | 仅标题、仅用户正文、仅助手正文命中 | 均返回正确会话；服务/API 测试 |
| S03 | 超过侧栏第一页的旧对话 | 未加载历史仍能搜到；API 与端到端测试 |
| S04 | 多会话与多消息命中 | 会话去重，按会话更新时间排序；标题不加权，时间相同顺序稳定 |
| S05 | 一个会话多条消息命中 | 选最近命中消息及其第一个匹配，片段与跳转目标一致 |
| S06 | 中文短词、英文大小写、空白、通配符、emoji | 匹配与区间按第 4 节一致；跨前后端契约用例 |
| S07 | 已发送引用、quote-only、长引用截断 | 可搜索；定位引用快照，必要时临时展开后准确标记 |
| S08 | 删除、恢复、归档、临时草稿、思考与附件 | 严格遵守范围；恢复后可搜，旧分支不可搜 |
| S09 | 两个账户及查询中途登出 | 无越权、缓存串用或迟到响应泄漏 |
| S10 | 输入法、快速修改、清除、关闭、重开 | 不提交拼音中间态；旧结果不回写，查询与位置正确恢复 |
| S11 | 首次失败、无结果、分页失败 | 三种状态可区分；重试不丢已有有效结果 |
| S12 | ↑↓、Enter、Escape、Tab、读屏 | 选择、打开、关闭和焦点范围符合第 6 节 |
| S13 | 跨会话与当前会话结果 | 两者都定位；标题单独命中沿用普通打开行为 |
| S14 | 很长回复、重复词、跨 inline 节点、代码 | 精确定位代表命中文字，不能错误跳到第一条同词消息 |
| S15 | 滚动与高亮时间线 | Chrome 连续采样：滚动稳定后标黄、2 秒保持、1 秒淡出，无文字几何变化 |
| S16 | 切换目标、用户滚动、减少动态效果 | 旧定位取消、无自动追赶、无残留标记；尊重 reduced motion |
| S17 | 当前 Run 流式及终态详情刷新 | 搜索不取消服务端 Run，不丢草稿，定位后不被拉回底部 |
| S18 | 搜索后目标删除、归档或改变 | 按第 7 节降级；不标错内容、不假报成功 |
| S19 | 手机软键盘、短视口、长标题 | 输入/关闭可用，结果可滚动，无横向溢出或双重滚动 |
| S20 | 搜索性能与只读性 | 基准记录满足目标；搜索、打开不更新会话时间或消息 |

单元测试验证匹配、权限、分页、状态竞争与计时逻辑；真实 Chrome 验证滚动位置、文字范围、几何及颜色时间线。不能只用 jsdom 或静态截图声称定位高亮完成。
