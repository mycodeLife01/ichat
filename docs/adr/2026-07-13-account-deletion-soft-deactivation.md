# ADR: 注销 = 软停用 + 延后物理清除

日期：2026-07-13
状态：已接受
相关：`docs/handover/2026-07-13-password-reset-account-deletion.md`、`CONTEXT.md`（注销 / 停用）

## 背景

账户注销（用户主动终止账户）需要决定确认后对数据做什么。用户表通过级联外键
（`ON DELETE CASCADE`）连接会话、消息、run、run 事件、refresh token、认证令牌等
全部业务数据：一次物理 `DELETE` 会立即、不可逆地清除该用户的一切记录。误操作、
被盗会话恶意注销、或用户反悔都没有任何挽回窗口。

## 备选方案

1. **立即物理删除**：确认链接点击后 `DELETE FROM users`，级联清除全部数据。
   最彻底，但完全不可逆；误删或被害删除无法恢复，且删除大量级联行的事务在
   高数据量用户上代价不可控。
2. **软注销（停用 + 数据保留）**：置 `users.is_active = false` 并吊销全部凭证，
   数据原样保留。既有的「停用用户被 login / refresh / 当前用户依赖拒绝」机制
   即为注销的执行面，无需新增访问控制。
3. **冷静期 + 周期物理清除**：软注销之上再加冷静期（如 30 天）与周期清除任务，
   到期后物理删除。最终形态，但本期没有清除任务的调度与验收基础，且冷静期内
   自助恢复需要独立的产品与安全设计。

## 决策

本期采用**方案 2：软注销**。确认注销后：

- `users.is_active = false`（唯一的状态位，无新增字段）；
- 吊销该用户全部未过期 refresh token；
- 撤销该用户**所有用途**的 active 认证令牌（验证 / 重置 / 注销）；
- **公开头像是即时物理删除例外**：注销事务清空当前头像键、使全部在途头像上传失效，并创建持久化补偿，负责删除 R2 成品对象和按完整 URL purge Cloudflare CDN。会话、消息、run 等其他业务数据仍按软停用语义保留。

头像例外来自公开资源的隐私边界：仅清空数据库引用不能阻止持有旧 CDN URL 的访问者继续读取长期缓存。该例外不扩展为本期的通用账户数据物理清除。

其他业务数据的物理清除（方案 3 的冷静期 + 周期任务）**明确留作后续迭代**，接续点：

- 停用时间可由 `users.updated_at` 或后续新增的 `deactivated_at` 字段确定；
- 清除任务可复用 celery-beat 的单实例周期调度模式（先例：outbox sweep）；
- 冷静期内恢复账户须设计**显式恢复入口**，不得借道密码重置
  （已停用账户申请重置是静默不发信的，见交接文档）。

## 后果

- **业务数据可恢复**：注销后反悔可由运维手工恢复（`is_active = true`），会话、消息等保留数据未丢失；公开头像已永久删除，恢复账户后不会自动恢复，用户需重新上传。
- **反直觉之处**：「删除账户」并未删除数据——产品文案与隐私承诺必须避免
  「已删除全部数据」的表述，直至物理清除迭代落地。
- **权衡**：数据保留期间仍占用存储并承担合规义务；这是为可恢复性支付的
  显式成本，由后续物理清除迭代收敛。
- 停用语义与运营封禁共用 `is_active` 位，当前无法区分；若将来需要区分
  「用户自愿注销」与「运营停用」，需要补充来源字段。
