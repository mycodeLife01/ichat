# 验证证据

首版来源为 `7d01cfa6b542f98ee67d8a54a437748a60f4c190`。`catalog/sources.json` 记录提取模块和来源 SHA-256；`catalog/baseline.json` 记录完整 Design 内容指纹。文件哈希用于辨认版本，不能证明两个不同程序的视觉语义相同。

`test:parity` 同时运行正式前端原组件与 Design 独立组件；参考入口在 `frontend/tests/design-reference/`。两侧仅共用合成数据、场景描述和测试结果回调，原版仍使用自己的 AppShell、认证、消息和管理组件。没有用 Design 截图冒充原版基线，也没有要求两端复用展示组件来让测试自然通过。

固定条件：Playwright 自带 Chromium、同一操作系统、1440×900 / 390×844、DPR 1、中文、Asia/Shanghai、浅色、固定样本日期。认证背景固定 performance 时点；循环 CSS 动画暂停在相同时点，有限过渡推进到结束；配对前统一滚动位置、移开鼠标并取消焦点，焦点和交互另外测试。站点图标用同一个本地 PNG，避免 SVG 的异步栅格缓存及外部网络造成差异。

图片比较逐像素、逐通道执行。使用 Pixelmatch 的感知颜色阈值 0.05，includeAA=true（抗锯齿边缘也参与比较）；阈值以上的不同像素必须为零。这个小阈值用于吸收模糊与边缘的栅格舍入，不能证明数学上的完全相等。没有遮挡 mask，没有允许错位的差异面积比例。每次输出 source/design/diff PNG 和原始/容差后差异数量。失败必须查图，不能自动更新截图掩盖回归。

- `output/parity/`：每个配对场景的原版图、Design 图、差异图、metrics.json；失败保留 trace。
- `output/visual/`：场景截图、关键交互 trace、断点布局和思考标题时间线数据。
- `output/parity-report.json`、`output/visual-report.json`：机器可读结果。
- CI 无论通过与否上传上述文件，版本与该次 CI commit 关联。本地输出不进入 Git，避免仓库累积大量截图。

配对截图证明列出的固定场景；`test:visual` 的所有场景渲染检查只证明无崩溃、无外部请求和页面溢出，不冒充每一状态都做过像素配对。浏览器交互测试验证重要连续流程，原版单测继续覆盖展示组件的既有行为。

实际 iOS 软键盘、系统分享、原生选区菜单和剪贴板权限不能由窄 Chromium 视口证明。此版没有真机验收证据；这些能力沿用原版实现与已知限制，在相关新需求中单独真机验证。设计中的成功上传/邮件/后台配置只是可见结果演示，不证明业务服务正确。
