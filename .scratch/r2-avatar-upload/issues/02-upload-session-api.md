# 上传会话 API、预签名直传与防滥用

Type: task

Status: completed

Blocked by: 01

## What to build

在当前用户认证资源下实现创建上传会话、确认上传和查询状态三个端点。只有已登录、active 且邮箱已验证的用户可以创建会话。

前端只提交裁剪后 `1024×1024 WebP` Blob 的准确字节数。服务端签发固定 `image/webp`、10 分钟有效的私有 R2 PUT URL。确认时通过 HEAD 核对对象键、大小、内容类型和 ETag，并在数据库事务中把会话从 pending 条件更新为 queued；事务提交后尽力投递媒体任务。

## Acceptance criteria

- [x] 创建端点只接受不超过 2 MiB 的正整数字节数，不能由客户端指定 bucket、对象键或内容类型。
- [x] 只有 active、邮箱已验证的当前用户能创建会话；未验证用户得到稳定的业务错误。
- [x] 创建会话执行每用户每小时 10 次、每 IP 每小时 30 次 Redis 限流；Redis 故障时 fail-closed。
- [x] 新会话创建时，更早的未完成会话失去发布资格；并发创建仍只留下一个当前有效会话。
- [x] 预签名 URL 有效 10 分钟，会话有效 30 分钟，并返回前端必须携带的签名头和到期时间。
- [x] 确认端点验证 ETag、实际大小、固定内容类型和当前会话资格；不接收裁剪坐标或原文件名。
- [x] 确认事务将 pending 置为 queued；提交后发布失败不会丢失数据库事实，后续恢复任务可重新投递。
- [x] 重复确认保持幂等，不会重复创建任务或覆盖更新。
- [x] 查询端点仅允许会话所有者访问，返回稳定状态、错误代码及成功后的头像 URL。
- [x] 注册、登录、刷新、当前用户查询和资料更新响应增加可空头像 URL，既有客户端字段保持兼容。
- [x] HTTP API 测试覆盖认证、邮箱验证门槛、限流、Redis 故障、对象校验、并发和幂等行为。
