06 / DECISION TABLE

颜色选择由“发生了什么”决定

开发时先判断状态语义和影响范围，再选择组件；不允许业务组件直接挑一个绿色或红色。

语义 典型事件 默认组件 视觉规则
普通 选中、hover、加载完成 灰阶 surface / neutral toast 不使用成功色；选中不等于成功
成功 复制成功、保存成功、邮箱已验证 短暂操作用中性 Toast；持续状态用 success notice Check 图标始终存在，绿色只用于值得保留的状态
失败 字段错误、请求失败、生成失败 Inline error / error toast / process notice 文字＋图标＋文案，不依赖颜色单通道
提醒 邮箱未验证、存在风险但尚未失败 Persistent warning notice 与 danger 分离，不使用删除红
07 / MIGRATION MAP

改造会落到哪些组件

建议先改基础设施，再迁移高频交互面，最后收口业务页面中的局部样式。

第一层 · 令牌与状态模型

建立圆角、颜色、阴影、遮罩令牌；Toast action 增加 tone。

  • styles/global.css
  • ui/classes.ts
  • ui/state.ts
  • ui/Toast.tsx

第二层 · 高频共享组件

统一侧边栏、菜单、Composer、Dialog、BottomSheet 的交互表面。

  • conversations/Sidebar.tsx
  • conversations/UserMenu.tsx
  • ui/Composer.tsx
  • ui/ConfirmDialog.tsx
  • ui/BottomSheet.tsx

第三层 · 业务状态收口

迁移账号、分享、认证和消息状态，移除硬编码颜色与重复圆角。

  • conversations/AccountCard.tsx
  • conversations/MySharesCard.tsx
  • ui/ShareDialog.tsx
  • messages/StreamingMessage.tsx
  • auth/*.tsx

此页面是临时视觉说明，不代表生产代码已经完成迁移。建议确认这套层级后，再进入实际组件改造。
