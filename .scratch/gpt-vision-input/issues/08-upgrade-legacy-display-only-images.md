# 升级历史仅展示图片

## 目标

让视觉功能上线前的图片消息通过明确编辑或重新生成获得新的 GPT 图像输入，同时保持旧 Run 的附件提示事实不可变，避免更早不可读图片与更晚可读图片混合。

## 交付范围

1. 图片上下文增加 legacy 升级状态并返回当前分支最早的历史仅展示图片消息身份。
2. 普通发送继续允许 DeepSeek，但普通切换视觉模型返回 409 与稳定 machine code，并指向最早升级锚点。
3. 只有最早锚点允许选择视觉模型进行编辑或重新生成；新 Run 为该用户消息建立图像块快照并更新当前 Run 引用。
4. 按既有分支规则归档锚点之后的消息，旧 Run 与其附件提示 transcript 始终保持不变。
5. 新 Run 事务提交后立即成为当前有效输入；后续失败或取消不回退到旧提示块。
6. 前端提供锚定编辑、锚定重新生成和新建对话三个恢复入口。

## 验收

- [x] 有一条或多条 legacy 图片时，只能从当前分支最早一条开始升级。
- [x] 普通 GPT 切换和升级较晚图片均在任何分支变更前拒绝，并返回正确锚点。
- [x] 编辑与直接重新生成都能创建实际包含图像块的新 GPT Run，并更新消息当前 Run 引用。
- [x] 旧 DeepSeek Run 仍可查看原附件提示 transcript，未被重写或删除。
- [x] 升级 Run 失败或取消后，会话仍诚实保持视觉依赖。
- [x] 后续旧分支归档、附件生命周期和会话恢复行为符合既有语义。

## 非目标

- 本票不批量升级全部旧图片，也不让 GPT 静默追溯读取旧 Run 未见过的图片。
