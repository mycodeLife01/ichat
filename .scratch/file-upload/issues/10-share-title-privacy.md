# 分享与自动标题的附件隐私边界

## 目标

让含附件对话可以安全生成标题和公开分享，同时确保公开快照绝不授予附件内容、预览或
下载能力。

## 交付范围

1. 自动标题输入只包含用户文字、附件安全元数据（清洗后的文件名、格式、大小）和首条
   助手回复；不得再次注入派生全文、原件、签名 URL 或 parser metadata。
2. 分享快照为附件保存稳定占位元数据，能够表达附件存在、类型、大小和处理 warning；
   不保存 FileObject key、原件、派生文本、preview、下载 token 或可推导内部 ID。
3. 匿名分享 API 和页面仅展示占位卡片，没有 preview/download 操作，也不能通过文件
   许可 API 交换成签名 URL。
4. 创建含附件的分享时增加明确隐私确认，说明助手回复可能已经包含附件信息；该提示不
   试图过滤或重写既有 assistant 快照。
5. 分享删除、会话后续编辑和附件回收不改变已生成分享快照的稳定元数据，也不复活附件访问。

## 验收

- 标题 provider fake 断言只收到文字、附件元数据和助手回复，不收到文档全文或文件 URL。
- 分享数据库/API/schema/frontend 测试证明只存在占位元数据；匿名用户对原件、派生物和
  preview 的所有许可请求均拒绝。
- 含附件分享必须确认；无附件分享保持既有流程。确认文案覆盖“助手回复可能含附件信息”。
- 对话编辑、文件 detached/删除和分享撤销前后，公开快照均不出现失效签名 URL 或内部 key。
- 文档与图片占位表现一致，并能展示部分提取 warning；后端和前端全套检查通过。
