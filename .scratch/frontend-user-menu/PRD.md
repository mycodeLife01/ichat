# 前端个人中心与 UserMenu

Type: feature
Status: ready-for-agent
Blocked by: None

日期：2026-07-14
需求来源：`feat/frontend-user-menu` 分支上的方案 A「渐进浮层」原型评审
术语依据：根目录 `CONTEXT.md`（邮箱验证 / 改密 / 注销 / 停用）

## Problem Statement

当前侧栏只有直接退出入口，用户无法在聊天上下文中统一查看或管理账户资料、邮箱验证、改密、注销和自己创建的会话分享。相关后端能力大多已经存在，但缺少生产级前端入口；昵称与跨会话分享聚合还缺少必要的数据契约。

## Solution

采用已确认的方案 A「渐进浮层」：点击侧栏个人区域打开紧凑 UserMenu，再由菜单项打开按业务量自适应大小的居中 Card。菜单顶部用户信息只展示，不可点击；菜单项为账号、我的分享和退出登录。

实现按六个可独立演示的垂直切片推进：

1. 生产化 UserMenu 外壳并接通真实退出登录。
2. 交付账号概览、头像本地预览和邮箱验证入口。
3. 新增独立昵称字段并完成持久化修改。
4. 接通已登录改密。
5. 接通发起与确认注销。
6. 增加当前用户全部有效分享的聚合管理。

## Confirmed Decisions

- 采用方案 A「渐进浮层」，不保留 B/C 方案。
- `nickname` 是独立展示字段，不改变仍可用于登录的唯一 `username`；现有用户和新注册用户默认以 `username` 初始化昵称。
- 头像本期只实现文件选择和本地预览，不上传、不持久化。
- “我的分享”本期不增加查看次数统计；只展示现有领域数据支持的会话标题、创建时间和过期信息。
- 复制链接与撤销分享复用现有全局 Toast，文案分别为“链接已复制”和“已撤销分享”。
- 注销沿用既有软停用语义，不在前端引入物理删除或恢复能力。

## Proposed Test Seams

- React 用户界面缝：通过可访问角色操作真实组件，使用注入的 fake services 观察菜单、Card、Toast 和认证状态变化。
- 前端 API 客户端缝：以请求适配器替身验证新增或补齐的 HTTP 请求/响应契约。
- 后端 HTTP API 缝：使用 ASGI 客户端和真实 PostgreSQL，通过 API 响应及后续公开查询验证昵称与分享聚合行为。
- 最终浏览器 smoke：使用真实浏览器覆盖菜单、头像选择、分享撤销和退出确认的关键路径；该项作为验收证据，不新增实现耦合的测试缝。

## Out of Scope

- 头像文件上传、对象存储、裁剪和头像 URL 持久化。
- 分享访问次数采集与统计。
- 物理删除账号数据、冷静期和自助恢复。
- 密码重置入口与重置落地页（属于独立前端迭代）。
