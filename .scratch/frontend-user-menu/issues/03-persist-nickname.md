# 持久化修改昵称

Type: feature

Status: ready-for-agent

Blocked by: 02

## What to build

为账户增加独立的 `nickname` 展示字段，并在账号 Card 中完成持久化修改。昵称不参与登录、不要求唯一；既有账号和新注册账号默认以 `username` 初始化。保存成功后，当前认证会话、侧栏个人区域、UserMenu、账号 Card 和退出确认 Card 立即显示新昵称。

## Acceptance criteria

- [ ] 用户模型具备独立昵称字段；迁移对既有用户回填用户名，新注册用户默认使用注册用户名。
- [ ] 当前用户响应包含昵称；新增经过认证的资料更新能力，只允许修改自身昵称。
- [ ] 昵称 trim 后长度为 1–50 字符，允许与其他用户重复，且修改昵称不影响用户名或用户名登录。
- [ ] 前端保存成功后同时更新持久化认证会话和渲染状态，无需重新登录或刷新页面。
- [ ] 提交态防重复；校验错误与服务端失败在表单附近提供清晰反馈，失败时保留原昵称。
- [ ] 后端 HTTP API 测试通过更新后再次查询当前用户验证持久化与身份隔离；前端组件/API 测试覆盖成功和失败。
